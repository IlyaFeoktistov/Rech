# Спецификация Rech v0.1

Единственный источник истины о том, что компилятор Rech принимает **прямо
сейчас**. В отличие от [docs/GRAMMAR.md](GRAMMAR.md) (черновики синтаксиса
для того, что запланировано, но ещё не реализовано - там есть пометки
`[v0.1]`/`[шаг N]`) здесь пометок "планируется" нет: всё описанное ниже
работает и покрыто примерами в `examples/`. Обновляется в том же коммите,
где меняется реализация - так ведут спеку языка и другие проекты, например
Go: [go.dev/ref/spec](https://go.dev/ref/spec) - один нормативный документ,
а не набор идей вперемешку с тем, что уже есть.

## 1. Кодировка и имена файлов

- Исходный файл - UTF-8, без BOM.
- Исходный файл должен быть в нормализованной форме Unicode **NFC**
  (проверяется компилятором - `lexer.ValidateNFC`). Без этого правила два
  визуально одинаковых идентификатора или имени файла могут оказаться
  разными байтовыми строками - классический случай: буква "ё" как единый
  символ U+0451 против "е" + отдельный диакритический знак U+0308 - и тихо
  не совпасть друг с другом: в таблице символов, а позже - при разрешении
  импорта по имени файла. NFC выбран как единственная разрешённая форма,
  потому что это то, что по умолчанию выдают большинство редакторов и
  Linux-инструментов.
- Имя `.rech`-файла (без расширения) - только строчные буквы (кириллица или
  латиница), цифры и `_`: `имя_файла.rech`. Заглавные буквы запрещены -
  Windows и macOS по умолчанию не различают регистр в именах файлов, а Linux
  различает; когда имя файла станет ключом импорта в системе модулей
  (`использовать X из "имя_файла"`), такое рассогласование между
  платформами превратилось бы в трудноуловимый баг. Проверяется
  `compiler.validateSourceFileName`.
- Рекомендация для тех, кто клонирует репозиторий: выполнить один раз
  `git config core.quotepath false` **без `--global`** (т.е. только для
  этого репозитория) - иначе `git status`/`git diff` печатают кириллические
  пути восьмеричными escape-последовательностями вместо читаемого текста.
  Это настройка конкретного клона, не самого репозитория - git осознанно не
  даёт репозиторию навязывать поведение клиента, поэтому команду нужно
  выполнить в каждом новом клоне отдельно.

## 2. Лексика

### Разделитель инструкций

Внутри блока `{ ... }` соседние инструкции обязательно разделены хотя бы
одним переносом строки или `;` (можно сочетать - несколько переносов и `;`
подряд считаются одним разделителем). Без разделителя - ошибка компиляции,
а не молчаливая склейка в одну инструкцию: `переменная а = 5 переменная б = 3`
на одной строке без `;` - ошибка. Расстановка `{`/`}` при этом свободна:

```
если а > 3 {
    вывести "да"
}

если а > 3 { вывести "да" }
```

- обе формы допустимы, потому что разделитель нужен именно между
  инструкциями, а не вокруг скобок самих по себе.

### Комментарии

`// до конца строки`. Многострочных комментариев нет.

### Идентификаторы

Идентификатор - последовательность букв (кириллица и латиница на равных
правах, по `unicode.IsLetter`), цифр и `_`, не начинающаяся с цифры. Регистр
значим (`Пользователь` и `пользователь` - разные идентификаторы) - это
касается идентификаторов внутри кода и не связано с правилом для имён
файлов выше (там регистр запрещён вообще, здесь - значим, как обычно в
языках программирования).

### Литералы

| Литерал            | Пример           | Тип          |
|---------------------|-------------------|---------------|
| строковый           | `"привет"`        | `Строка`      |
| целочисленный       | `42`              | `Целое`       |
| с плавающей точкой  | `3.14`            | `Число`       |
| логический          | `истина` / `ложь` | `Логическое`  |

Escape-последовательности в строках: `\n`, `\t`, `\"`, `\\`. Перенос строки
внутри строкового литерала не поддерживается.

### Ключевые слова

| Слово          | Значение                                       |
|-----------------|-------------------------------------------------|
| `функция`       | объявление функции                             |
| `переменная`    | объявление переменной с инициализацией         |
| `вывести`       | напечатать значение выражения                  |
| `и`             | логическое И                                   |
| `или`           | логическое ИЛИ                                 |
| `не`            | логическое НЕ (унарное)                        |
| `истина`        | логический литерал "true"                      |
| `ложь`          | логический литерал "false"                     |
| `если`          | условная конструкция                           |
| `иначе`         | альтернативная ветка `если`                    |
| `пока`          | цикл с условием                                |
| `для`           | цикл по целочисленному диапазону               |
| `от`            | нижняя граница диапазона в `для`               |
| `до`            | верхняя граница диапазона в `для` (включительно)|
| `вернуть`       | досрочный выход из функции (без значения)      |
| `с`             | предлог перед аргументом естественного вызова  |
| `в`             | предлог перед аргументом естественного вызова  |
| `сущность`      | объявление сущности                            |
| `класс`         | синоним "сущность"                             |
| `имеет`         | секция полей в объявлении сущности             |
| `создать`       | конструктор экземпляра сущности                |
| `этот`          | ссылка на объект внутри тела метода            |

Ключевые слова зарезервированы - использовать их как имена переменных или
функций нельзя.

## 3. Операторы и приоритет

От низшего приоритета к высшему (раньше в списке - слабее связывает):

| Приоритет  | Операторы                   | Ассоциативность                    |
|------------|-------------------------------|-------------------------------------|
| 1 (низший) | `или`                         | левая                               |
| 2          | `и`                            | левая                               |
| 3          | `не` (унарный, префиксный)    | -                                    |
| 4          | `== != < > <= >=`             | не цепочная (один раз на уровень)   |
| 5          | `+ -` (бинарные)               | левая                               |
| 6          | `* /`                          | левая                               |
| 7 (высший) | `-` (унарный минус)            | -                                    |

Скобки `( ... )` группируют явно и перекрывают любой приоритет.

## 4. Грамматика (EBNF)

```
program        := { sep } { ( function | entity ) { sep } }
function       := "функция" IDENT [ "(" [ params ] ")" ] [ ":" type_name ] { sep } block
params         := param { "," param }
param          := IDENT ":" type_name
type_name      := IDENT [ "<" type_name ">" ]
entity         := ( "сущность" | "класс" ) IDENT { sep } "{" { sep } [ fields_section ] { sep } { method { sep } } "}"
fields_section := "имеет" ":" field { sep field }
field          := IDENT ":" type_name
method         := IDENT "(" [ params ] ")" [ ":" type_name ] { sep } block
block          := "{" { sep } [ statement { sep statement } [ sep ] ] "}"
sep            := ( newline | ";" ) { newline | ";" }

statement      := var_decl | assign | field_assign | print_stmt
                | if_stmt | while_stmt | for_stmt | return_stmt | call_stmt | method_call_stmt
var_decl       := "переменная" IDENT "=" expr
assign         := IDENT "=" expr
field_assign   := ( IDENT | "этот" ) "." IDENT "=" expr
print_stmt     := "вывести" expr
if_stmt        := "если" expr block [ "иначе" block ]
while_stmt     := "пока" expr block
for_stmt       := "для" IDENT "от" expr "до" expr block
return_stmt    := "вернуть" [ expr ]
call_stmt      := call_expr
call_expr      := IDENT "(" [ expr { "," expr } ] ")"
method_call_stmt := method_call_expr

expr           := or_expr
or_expr        := and_expr { "или" and_expr }
and_expr       := not_expr { "и" not_expr }
not_expr       := "не" not_expr | comparison
comparison     := additive [ ("==" | "!=" | "<" | ">" | "<=" | ">=") additive ]
additive       := multiplicative { ("+" | "-") multiplicative }
multiplicative := unary { ("*" | "/") unary }
unary          := "-" unary | postfix
postfix        := primary { "." IDENT [ "(" [ expr { "," expr } ] ")" ] }
primary        := INT | FLOAT | STRING | "истина" | "ложь" | IDENT | "этот"
                | call_expr | new_expr | "(" expr ")"
new_expr       := "создать" type_name "(" [ expr { "," expr } ] ")"
method_call_expr := postfix   (* postfix, оканчивающийся на ".имя(...)" *)
```

Постфиксный `.` (`field_access` ниже) применяется к любому первичному
выражению, в том числе к результату `call_expr`/`new_expr`.

Программа должна содержать функцию `главная` - она становится точкой входа
(транслируется в C `main`). Другие функции разрешены (транслитерируются в
`rech_<имя>`) и могут вызывать друг друга независимо от порядка объявления
в файле (включая взаимную рекурсию, см. "Вызов функции" ниже).

### Параметры и тип результата

- Параметр объявляется как `<имя>: <Тип>`. Имя параметра - одно из шести
  падежных вопросительных слов: `кто`, `кого`, `кому`, `кем`, `где`, `что` -
  это одновременно и имя параметра, и его падежная роль при естественном
  вызове (в оставшейся части шага 3). `кого` и `что` - оба винительный
  падеж (различаются одушевлённостью существительного-аргумента), поэтому
  у одной функции не может быть обоих сразу - как и любых двух параметров с
  одинаковым падежом.
- Тип результата объявляется как `: <Тип>` после списка параметров (или
  сразу после имени функции, если параметров нет). Единственные доступные
  типы для параметров и результата - `Строка`, `Целое`, `Число`,
  `Логическое` (те же, что и для переменных); типы, приходящие с сущностями
  (шаг 4), сюда пока не входят.
- `главная` - точка входа с фиксированной C-сигнатурой: она не может
  объявлять параметры или тип результата.
- Функция с объявленным типом результата должна синтаксически заканчиваться
  инструкцией `вернуть <выражение>` этого типа. Это простая проверка
  последней инструкции тела, а не полный анализ всех путей выполнения
  (`если`/`иначе` с `вернуть` в обеих ветках как последняя пара инструкций
  функции этой проверкой не покрывается) - настоящая flow-sensitive проверка
  появится вместе с IR на шаге 5.

### Вызов функции (строгий синтаксис)

- `<имя>(<арг>, ...)` - вызов функции по имени с позиционными аргументами.
  Как выражение - если у функции объявлен тип результата (иначе её нельзя
  использовать там, где ожидается значение); как самостоятельная инструкция
  (`call_stmt`) - для любой функции, результат в этом случае отбрасывается.
- Число и типы аргументов должны точно совпадать с объявлением функции (без
  неявных преобразований, как и везде в языке).
- Функции можно вызывать друг друга независимо от порядка объявления в
  файле, включая взаимную рекурсию - компилятор эмитит C-прототипы всех
  функций до их тел.
### Вызов функции (естественный синтаксис)

- `<имя> { [<предлог>] <аргумент> }` - тот же вызов, что и `<имя>(<арг>, ...)`,
  без скобок и без фиксированного порядка аргументов: каждый аргумент -
  словоформа-ссылка на уже объявленную переменную, и то, к какому параметру
  она относится, определяется её падежом (движок `internal/morph`, шаг 1.5),
  а не позицией в предложении.
- В отличие от строгого вызова, естественный вызов разбирается **только**
  как самостоятельная инструкция - его нельзя использовать там, где нужно
  значение (аргумент другого вызова, `переменная x = ...`, `вывести ...`).
  Результат вызова, который нужно использовать как значение, вызывается
  строго - см. `examples/функции/естественный_вызов.rech`.
- Предлог перед аргументом (`с`, `в`) необязателен и не влияет на
  сопоставление - падеж словоформы определяет роль сам по себе. Список
  предлогов - маленький курируемый набор, а не попытка перечислить все
  предлоги русского языка.
- Аргумент естественного вызова - **только IDENT**, ссылающийся на
  переменную, зарегистрированную как существительное (объявленную через
  `переменная` или как переменную цикла `для`). Литералы (`1`, `"текст"`) в
  качестве аргументов естественного вызова не поддерживаются - у них нет
  падежной формы, к которой можно было бы что-то привязать; для них
  используется строгий вызов.
- Вся фраза естественного вызова должна умещаться в одну строку.
  Многострочное продолжение фразы по значимому отступу - см.
  [docs/GRAMMAR.md](GRAMMAR.md), пока не реализовано.
- Глагол/имя функции в естественном вызове пишется ровно так, как объявлена
  функция (`функция зарегистрировать(...)` вызывается только как
  `зарегистрировать ...`) - спряжение (`зарегистрировал`, `зарегистрирует`)
  для обычных функций не распознаётся; это появится вместе с методами
  сущностей и стандартной библиотекой (`internal/morph.SystemVerbs`, шаг 4+).
- `кого` и `что` - оба винительный падеж, различаются одушевлённостью
  существительного-аргумента (курируемая таблица `internal/morph.AnimacyOf`,
  по умолчанию - неодушевлённое): словоформа, чья одушевлённость не
  совпадает с ожидаемой параметром, к нему не привязывается.
- Если словоформа аргумента не опознана словарём или не подходит по падежу
  ни одному ещё не заполненному параметру - ошибка компиляции.

## 5. Типы и семантика

- Типы: `Строка`, `Целое` (64-битное целое), `Число` (64-битное с плавающей
  точкой), `Логическое`.
- Тип переменной выводится из литерала-инициализатора (literal-based
  inference) и фиксируется навсегда: повторное присваивание значения другого
  типа - ошибка компиляции, неявных преобразований нет.
- Исключение из "неявных преобразований нет": арифметика между `Целое` и
  `Число` даёт `Число` (операнд `Целое` приводится явно в сгенерированном C,
  сам язык это не считает пользовательским преобразованием типа).
- `+` между двумя `Строка` - конкатенация, а не арифметика.
- `==`/`!=` определены для `Строка` (сравнение содержимого, не указателей),
  `Целое`/`Число` и `Логическое`. `< > <= >=` - только для `Целое`/`Число`.
- `и`/`или`/`не` - только для `Логическое`.
- Переменная должна быть объявлена (`переменная`) до первого использования
  и до первого присваивания.

### Блочная область видимости

- `если`/`иначе`/`пока`/`для` вводят собственную область видимости, как
  блоки `{ }` в C: переменная, объявленная внутри такого блока, не видна
  после его закрывающей `}`.
- Затенение (shadowing) разрешено: `переменная x = ...` внутри блока может
  повторно использовать имя, уже занятое во внешней области - это заводит
  новую переменную для внутреннего блока, а не ошибка.
- Переменная цикла `для <имя> от ... до ...` имеет тип `Целое` и видна
  только внутри тела цикла.

### Условия и границы диапазона

- Условие `если`/`пока` должно быть выражением типа `Логическое` - иначе
  ошибка компиляции (`если 1 { ... }` не работает, в отличие от C).
- Обе границы `для ... от X до Y` должны быть `Целое`; диапазон включает
  обе границы (`для i от 1 до 5` - это `i = 1, 2, 3, 4, 5`). Если `X > Y`,
  тело цикла не выполняется ни разу.
- Цепочки `иначе если` нет - вложенность через `если` внутри блока `иначе`.

### `вернуть`

- `вернуть` без значения - досрочно завершает выполнение функции; допустим
  только у функции без объявленного типа результата. В сгенерированном C
  транслируется в `return 0;` - 0 здесь техническая заглушка (функция без
  объявленного результата всё равно объявлена в C как `int`, чтобы
  выпадение с конца функции не было неопределённым поведением), а не
  значение, которое язык обещает как результат.
- `вернуть <выражение>` - допустим только у функции с объявленным типом
  результата; тип выражения должен совпадать с объявленным типом результата
  (без неявных преобразований, как и везде).

## 6. Сущности

- `сущность Имя { имеет: ... }` объявляет сущность; `класс` - точный синоним
  `сущность` (одна и та же конструкция, выбор слова - вопрос стиля).
- Поля объявляются под `имеет:`, каждое - `имя: Тип` на своей строке (или
  через `;`). Типы полей - те же, что и для переменных/параметров
  (`Строка`, `Целое`, `Число`, `Логическое`).
- Секция `имеет:` использует **значимый отступ**, а не список в скобках:
  поле принадлежит секции, только если оно отступлено строже, чем само
  слово `имеет`; строка на той же глубине отступа - уже не поле, а
  следующий член сущности (метод). Это тот же принцип, что и в остальном
  языке ("Разделитель инструкций" выше), только граница секции определяется
  отступом, а не ключевым словом или скобкой.
- `имеет:` необязательна (сущность без полей - `сущность Имя {}` - тоже
  допустима).

### Создание экземпляра и чтение поля

- `создать Тип(значение1, значение2, ...)` - конструктор: создаёт значение
  сущности. Аргументы **позиционные**, по порядку полей в `имеет:` (как у
  обычного вызова функции - не через падежное сопоставление); число и
  типы аргументов должны точно совпадать с объявленными полями.
- `receiver.поле` - чтение поля; тип выражения - объявленный тип поля.
  `receiver` - произвольное выражение сущностного типа (переменная,
  результат `создать Тип(...)`, ...).
- Сущности - **значения**, не ссылки: присвоить переменной, передать в
  функцию, вернуть - копия, как структура в C. Исключение - получатель
  метода (ниже): его мутация видна после возврата из метода, иначе будущий
  typestate (`этот становится авторизованным`, шаг 4.1) не имел бы смысла.
- `receiver.поле = значение` - присваивание полю; тип значения должен точно
  совпадать с объявленным типом поля (без неявных преобразований, как и
  везде). `receiver` - переменная сущностного типа, доступ к полю
  (`x.вложенное.поле = ...`) или `этот` внутри метода.

### Методы и `этот`

- Метод объявляется прямо в теле сущности, без ключевого слова - так же,
  как функция (`имя(<парам>: <Тип>, ...): <ТипВозврата> { <тело> }`), но
  скобки параметров всегда обязательны, даже без параметров (`метод()`).
  Отличается от поля отсутствием обёртки `имеет:` и наличием `(...)`/тела.
- `receiver.метод(арг1, ...)` - строгий вызов метода; как выражение, если у
  метода объявлен тип результата, или как самостоятельная инструкция.
  Число и типы аргументов проверяются строго, как и для функций.
  Естественный вызов метода (`receiver метод ...`) не реализован.
- `этот` - зарезервированное слово, валидное только внутри тела метода:
  ссылка на объект, у которого этот метод вызван. `этот.поле` - то же самое
  чтение/присваивание поля, что и `receiver.поле` снаружи. Единообразно, не
  согласуется по роду сущности (`этот`/`эта`/`это`).
- Получатель метода передаётся во внутреннем сгенерированном C **по
  указателю** (в самом Rech никаких указателей не видно) - поэтому
  мутация поля через `этот.поле = значение` внутри метода видна вызывающему
  коду после возврата из метода. Получателем вызова метода и получателем
  присваивания полю может быть только переменная, доступ к полю или
  `этот` - не результат вызова функции/конструктора/другого метода
  (у него нет постоянного адреса).

## 7. Обобщённый синтаксис типа

- Имя типа может быть параметризовано: `Тип<Аргумент>` (например,
  `Список<Целое>`) - там, где сейчас ожидается имя типа (параметр функции/
  метода, поле сущности, тип результата, `создать Тип(...)`). Кодируется
  как одна строка ("Список<Целое>") - AST не получает отдельного узла для
  этого, backend сам разбирает и резолвит строку.
- В этой версии - только один аргумент типа (нужно для встроенных
  коллекций, шаг 4.2); список аргументов через запятую (`Словарь<K,V>`) -
  не реализован.
- Единственные встроенные generic-шаблоны - коллекции (раздел 8 ниже);
  пользовательских generic-типов в языке пока нет вообще.

## 8. Коллекции

- `Список<T>` - динамический массив. Создаётся как обычная сущность -
  `создать Список<Целое>()` (пустой, без начальных значений). Методы:
  `добавить(значение: T)`, `получить(индекс: Целое): T`,
  `установить(индекс: Целое, значение: T)`, `длина(): Целое`,
  `пусто(): Логическое`.
- Элемент `T` в этой версии - только встроенный тип (`Строка`, `Целое`,
  `Число`, `Логическое`); сущности как элементы (`Список<Пользователь>`) не
  поддерживаются - в языке пока и так нет сущности как типа параметра/поля/
  результата ни в одном другом контексте, это не специфичное для коллекций
  ограничение.
- `получить`/`установить` с индексом вне `[0, длина())` - аварийное
  завершение процесса с сообщением на stderr (`exit(1)`) - в языке ещё нет
  исключений (шаг 14), это осознанно временное, но безопасное поведение.
- Реализация - мономорфизация: для каждой конкретной инстанциации
  (`Список<Целое>`, `Список<Строка>`, ...), встречающейся в программе,
  компилятор один раз генерирует свою C-структуру и функции (растущий
  массив, `realloc` с удвоением ёмкости при заполнении). Внутреннее
  представление не имеет полей, доступных из Rech (`.поле` к `Список<T>` не
  применяется) - только методы.
- Цикл `для x в список { ... }`, `Стопка<T>`, `Очередь<T>` - в работе,
  см. [docs/ROADMAP.md](ROADMAP.md), Шаг 4.2.

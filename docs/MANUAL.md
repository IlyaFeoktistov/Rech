## 1. Введение и философия

### Зачем ещё один язык программирования

Почти весь мир программирования говорит на английском синтаксисе - не
только ключевыми словами (`if`, `while`, `return`), но и самим порядком
слов и логикой построения фразы. Для носителя русского это не нейтральный
выбор алфавита, а навязанный чужой грамматический строй: жёсткий порядок
слов (подлежащее - сказуемое - дополнение) там, где русский язык устроен
свободнее именно благодаря падежам, отсутствие рода и числа там, где
русская речь ими пронизана насквозь.

Rech - попытка спроектировать язык программирования, в котором русская
грамматика не косметика («переведём ключевые слова на русский») и не
транслитерация, а часть механизма языка: то, что реально влияет на то, как
разбирается и проверяется программа.

### Ключевой принцип: грамматика - механизм, а не украшение

Если просто перевести `if`/`while`/`return` на `если`/`пока`/`вернуть`, не
изменив ничего в самой модели языка, - получится английский синтаксис в
русской графике, не русский язык программирования. Настоящая проверка
принципа - **естественный вызов функции** (раздел 7): в русской фразе
«оформить заказ клиенту» роль каждого слова относительно глагола
определяется не позицией в предложении, а падежом словоформы (винительный
- «что оформляем», дательный - «кому») - поэтому порядок слов свободен:
«клиенту оформить заказ» значит то же самое. Чтобы синтаксис языка
программирования умел так же, компилятору нужен настоящий морфологический
анализ словоформ (падеж, число, род, вид), а не жёсткий шаблон фразы с
предлогами на фиксированных местах - шаблон понимает только один,
заранее предусмотренный порядок слов, то есть остаётся английским по духу,
просто с русской лексикой. Поэтому морфологический движок
(`internal/morph`) - не поздняя надстройка, а часть языка, вынесенная
на архитектурном уровне рано, до того как строится сам синтаксис вызова.

Отсюда и второй практический принцип: словарь, которым оперирует движок,
**конечен и известен на этапе компиляции** - это идентификаторы, объявленные
в самой программе, плюс небольшой курируемый словарь стандартных глаголов
и слов. Rech не пытается разобрать произвольный русский текст (это открытая
лингвистическая задача, не решаемая без ML) - склонение и спряжение
конкретного, заранее известного набора слов - конечная, каталогизированная
задача с известными исключениями, и именно поэтому она разрешима в
компиляторе без вероятностных моделей.

### Два синтаксиса - одно дерево

У Rech два представления одного и того же вызова функции:

- **строгий** (`оформить(заказ, клиент)`) - позиционный, без грамматики,
  как в любом другом языке;
- **естественный** (`оформить заказ клиенту`) - падежное сопоставление,
  свободный порядок слов.

Это не два разных языка и не «синтаксический сахар» одного через другой -
оба разбираются в одно и то же дерево разбора (AST). Родной синтаксис можно
писать сразу, а строгий - не запасной вариант «для тех, кому лень», а
основа: естественный вызов - это то же самое дерево, увиденное через
падежи вместо позиций.

### Что дальше в этом руководстве

Дальше - по порядку: как собрать первую программу, лексика, типы,
выражения, управление потоком, функции (оба синтаксиса вызова), сущности,
встроенные коллекции и функции, внешние функции, модули, тестирование,
интерфейс командной строки. Каждый раздел даёт то, что **уже работает** в
v0.1 - не то, что запланировано (это в [docs/ROADMAP.md](ROADMAP.md)).

## 2. Первая программа и сборка

Нужен установленный системный C-компилятор (`cc`, `clang` или `gcc` в
`PATH`, либо переменная окружения `CC`) - Rech v0.1 транспилирует в C и
собирает результат настоящим компилятором, а не интерпретирует байткод
напрямую (кроме `rech test`, раздел 14).

`examples/основы/привет.rech`:

```
функция главная
{
    вывести "Привет, мир!"
}
```

Собрать и сразу запустить:

```sh
rech run examples/основы/привет.rech
```

```
Привет, мир!
```

Собрать без запуска:

```sh
rech build examples/основы/привет.rech
```

даёт исполняемый файл `examples/основы/привет` (на Windows - с расширением
`.exe`) рядом с исходником. Промежуточный `.c`-файл по умолчанию удаляется
после успешной сборки; флаг `--keep-c` оставляет его - удобно, чтобы
посмотреть, во что на самом деле компилируется программа.

Программа без явной `главная` тоже допустима - инструкции верхнего уровня
собираются в неё автоматически:

```
переменная а = 5
вывести а
```

работает так же, как `функция главная { переменная а = 5; вывести а }`.

## 3. Лексика

### Кодировка и имена файлов

- Исходный файл - UTF-8 без BOM, обязательно в форме Unicode **NFC**
  (проверяется компилятором) - иначе визуально одинаковые идентификаторы
  (например, «ё» как единый символ против «е» + отдельный диакритический
  знак) могут оказаться разными байтовыми строками.
- Имя `.rech`-файла (без расширения) - только строчные буквы (кириллица или
  латиница), цифры и `_`. Заглавные буквы запрещены - иначе на Windows/macOS
  (не различают регистр в путях) и Linux (различает) один и тот же импорт
  вёл бы себя по-разному.

### Разделитель инструкций

Внутри блока `{ ... }` соседние инструкции обязательно разделены хотя бы
одним переносом строки или `;` (можно сочетать). Без разделителя - ошибка
компиляции, а не молчаливая склейка в одну инструкцию. Расстановка `{`/`}`
свободна - `если а > 3 { вывести "да" }` и многострочная форма с блоком
равноправны, разделитель нужен именно между инструкциями, а не вокруг
скобок.

### Комментарии

`// до конца строки`. Многострочных комментариев нет.

### Идентификаторы

Последовательность букв (кириллица и латиница на равных правах), цифр и
`_`, не начинающаяся с цифры. Регистр значим (`Пользователь` и
`пользователь` - разные идентификаторы) - в отличие от правила для имён
файлов выше, где регистр запрещён вообще.

### Литералы

| Литерал | Пример | Тип |
|---|---|---|
| строковый | `"привет"` | `Строка` |
| целочисленный | `42` | `Целое` |
| с плавающей точкой | `3.14` | `Число` |
| логический | `истина` / `ложь` | `Логическое` |

Escape-последовательности в строках: `\n`, `\t`, `\"`, `\\`. Перенос строки
внутри строкового литерала не поддерживается.

### Ключевые слова

`функция`, `переменная`, `вывести`, `и`, `или`, `не`, `истина`, `ложь`,
`если`, `иначе`, `пока`, `для`, `от`, `до`, `вернуть`, `утверждать`, `с`,
`в`, `сущность`, `класс`, `имеет`, `новый`/`новая`/`новое`/`новые`, `этот`,
`приватный`/`приватная`/`приватное`/`приватные`,
`публичный`/`публичная`/`публичное`/`публичные`, `использовать`, `из`,
`как`, `внешняя`. Зарезервированы - использовать их как имена переменных
или функций нельзя.

## 4. Типы

Встроенные примитивы: `Строка`, `Целое` (64-битное целое), `Число`
(64-битное с плавающей точкой), `Логическое`, `Файл` (непрозрачный
дескриптор, раздел 11.4).

- Тип переменной выводится из литерала-инициализатора и фиксируется
  навсегда: повторное присваивание значения другого типа - ошибка
  компиляции. Неявных преобразований нет вообще, с одним исключением:
  арифметика между `Целое` и `Число` даёт `Число` (языком это не считается
  пользовательским преобразованием типа).
- `Строка` сравнивается по содержимому (`==`/`!=`), не по указателю; `+`
  между двумя `Строка` - конкатенация.
- Помимо примитивов, тип может быть именем объявленной **сущности**
  (раздел 8) или **generic-инстанциацией встроенной коллекции** (раздел 10)
  - `Список<Целое>`, `Стопка<Строка>` и т. п.

## 5. Выражения и операторы

От низшего приоритета к высшему (раньше в списке - слабее связывает):

| Приоритет | Операторы | Ассоциативность |
|---|---|---|
| 1 (низший) | `или` (синоним `\|\|`) | левая |
| 2 | `и` (синоним `&&`) | левая |
| 3 | `не` (унарный) | - |
| 4 | `== != < > <= >=` | не цепочная |
| 5 | `\|` (побитовое ИЛИ, только `Целое`) | левая |
| 6 | `^` (побитовое искл. ИЛИ, только `Целое`) | левая |
| 7 | `&` (побитовое И, только `Целое`) | левая |
| 8 | `<< >>` (сдвиги, только `Целое`) | левая |
| 9 | `+ -` (бинарные) | левая |
| 10 | `* /` | левая |
| 11 (высший) | унарный `-`, `~` (только `Целое`), `++ --` | - |

`&&`/`||` - точные синонимы `и`/`или` (тот же токен), не отдельные
операторы. Скобки `( ... )` группируют явно и перекрывают любой приоритет.

- `/` между `Целое` и `Целое` с делителем `0` - аварийное завершение
  процесса (в языке пока нет исключений, раздел 16), а не неопределённое
  поведение. `/` между `Число` и `Число` на `0.0` - не проверяется,
  результат по IEEE 754 (`±бесконечность`/не-число).
- `==`/`!=` - для `Строка`, `Целое`/`Число`, `Логическое`. `< > <= >=` -
  только для `Целое`/`Число`.
- Побитовые операторы (`& | ^ << >>` бинарные, `~` унарный) - только для
  `Целое`; `Число` и любой другой тип - ошибка компиляции. Сдвиг на
  отрицательное число или на `>= 64` бит - неопределённое поведение
  сгенерированного C, языком не гарантируется.
- `имя++`/`имя--` (постфикс) и `++имя`/`--имя` (префикс) - только для уже
  объявленной переменной `Целое`/`Число` (не для поля сущности, не для
  результата вызова). Постфикс возвращает значение до изменения, префикс -
  после; в обоих случаях сама переменная меняется на `±1`.

## 6. Инструкции и управление потоком

### Переменные

`переменная <имя> = <выражение>` - объявление с обязательной
инициализацией. Переменная должна быть объявлена до первого использования
и до первого присваивания. `если`/`иначе`/`пока`/`для` вводят собственную
область видимости (как блоки `{ }` в C) - переменная, объявленная внутри,
не видна после закрывающей `}`; затенение (shadowing) разрешено.

### Условия

```
если <условие> {
    ...
} иначе {
    ...
}
```

`<условие>` должно быть типа `Логическое` - `если 1 { ... }` не работает, в
отличие от C. Цепочки `иначе если` нет синтаксически - вложенность через
`если` внутри блока `иначе`.

### Циклы

```
пока <условие> { ... }

для <имя> от <выражение> до <выражение> { ... }   // включительно с обеих сторон
```

Обе границы диапазона должны быть `Целое`; если начало больше конца, тело
не выполняется ни разу. Переменная цикла - `Целое`, видна только внутри
тела.

Цикл по коллекции - `для <имя> в <коллекция>` - описан в разделе 10
(встроенные коллекции) и в разделе 11.4 (`для <строка> в <Файл>`).

### `вернуть` и `утверждать`

`вернуть` без значения - только в функции без объявленного типа результата;
`вернуть <выражение>` - только в функции с объявленным типом результата,
тип должен совпадать точно.

`утверждать <выражение>` - `<выражение>` должно быть `Логическое`. Ложное
условие во время исполнения - аварийное завершение процесса с сообщением,
содержащим номер строки. Допустима в любой функции, не только в тестах -
тестовый файл (раздел 14) это просто соглашение об имени файла, не
отдельный синтаксис.

## 7. Функции

```
функция <имя>(<параметры>): <ТипРезультата>
{
    <тело>
}
```

Параметры и тип результата необязательны. `главная` - точка входа с
фиксированной сигнатурой: без параметров и типа результата на уровне
самого Rech (но см. раздел 11.4 - `аргумент`/`количество_аргументов` дают
доступ к настоящему `argv` собранного бинарника). Функции можно вызывать
друг друга независимо от порядка объявления в файле, включая взаимную
рекурсию.

### Параметры: падеж как часть объявления

Параметр объявляется в одной из трёх форм:

- `<падеж>: <Тип>` - падежное слово (`кто`, `кого`, `кому`, `кем`, `где`,
  `что`) одновременно и имя параметра, и его падежная роль при
  естественном вызове;
- `<падеж> <имя>: <Тип>` - падежная роль отдельно от отображаемого имени в
  теле функции: `оформить(кого пользователь: Пользователь)`;
- `<имя>: <Тип>` (не падежное слово) - параметр без падежной роли, доступен
  только по позиции.

`кого` и `что` - оба винительный падеж (различаются одушевлённостью
аргумента), поэтому у функции не может быть обоих сразу. Падежных
параметров - максимум 6 (по числу падежных слов); параметров без падежной
роли - сколько угодно.

### Строгий вызов

`<имя>(<арг>, ...)` - позиционные аргументы, как в любом другом языке. Как
выражение - если у функции объявлен тип результата; как самостоятельная
инструкция - для любой функции (результат отбрасывается). Число и типы
аргументов должны точно совпадать с объявлением.

### Естественный вызов

```
оформить заказ клиенту
```

- тот же вызов, что и `оформить(заказ, клиент)`, без скобок и без
фиксированного порядка: каждый аргумент - словоформа-ссылка на уже
объявленную переменную, а то, к какому параметру она относится,
определяется её падежом (движок `internal/morph`), не позицией в
предложении. Предлог перед аргументом (`с`, `в`) необязателен и не влияет
на сопоставление - падеж определяет роль сам по себе.

Правила естественного вызова:

- разбирается **только** как самостоятельная инструкция - использовать его
  там, где нужно значение (аргумент другого вызова, инициализация
  переменной, `вывести ...`), нельзя; для этого нужен строгий вызов;
- аргумент - **только** идентификатор переменной (или переменной цикла
  `для`), зарегистрированной как существительное - литералы (`1`,
  `"текст"`) не поддерживаются, у них нет падежной формы;
- сопоставление в два прохода: сначала аргументы связываются по падежу с
  ещё не занятыми падежными параметрами (порядок слов свободен), затем
  оставшиеся аргументы заполняют по порядку написания параметры без
  падежной роли (здесь порядок уже важен, падеж не проверяется);
- падежный параметр, не получивший подходящий по падежу аргумент, - ошибка
  компиляции, не угадывание «на что осталось»;
- глагол/имя функции пишется ровно так, как объявлена функция - спряжение
  для обычных функций (в отличие от методов сущности и системных глаголов)
  не распознаётся;
- вся фраза должна умещаться в одну строку.

Пример (`examples/функции/естественный_вызов.rech`):

```
функция поприветствовать(кого: Строка, где: Строка)
{
    вывести "Привет, " + кого + "! Добро пожаловать в " + где
}

функция главная
{
    переменная пользователь = "Илья"
    переменная система = "чат"

    // "пользователя" - винительный, одушевлённый -> связывается с "кого";
    // "в системе" - предложный -> связывается с "где" (предлог "в" -
    // необязательный, падеж работает и без него - переставьте слова
    // местами, смысл не изменится).
    поприветствовать пользователя в системе

    // То же самое строго (examples/функции/строгий_вызов.rech):
    поприветствовать(пользователь, система)
}
```

## 8. Сущности

```
сущность Пользователь           // "класс" - точный синоним "сущность"
{
    имеет:
        приватный пароль: Строка
        имя: Строка // без модификатора - публичное поле (по умолчанию)

    приватный проверить_пароль(попытка: Строка): Логическое
    {
        вернуть этот.пароль == попытка
    }

    публичный войти(попытка: Строка): Логическое
    {
        вернуть этот.проверить_пароль(попытка)
    }
}
```

### Поля

Каждое поле - `имя: Тип` на своей строке под `имеет:` (значимый отступ:
поле принадлежит секции, только если отступлено строже самого слова
`имеет`). Тип поля - примитив, generic-коллекция или имя **уже объявленной
выше в файле** сущности (сущности не могут ссылаться друг на друга
независимо от порядка объявления, в отличие от функций - взаимно
вложенные сущности не выразимы). `имеет:` необязательна.

### Конструктор и чтение поля

`<новый|новая|новое|новые> Тип(значение1, значение2, ...)` - форма
ключевого слова **согласуется по роду и числу** с именем сущности, как в
обычной русской речи: `новый Пользователь(...)`, `новая Сова(...)`, `новое
Окно(...)`, `новые Права(...)`. Аргументы - позиционные, по порядку полей,
либо именованные: `новый Пользователь(пароль: "секрет", имя: "Аня")`
(порядок не важен, смешивать с позиционной формой в одном вызове нельзя).

`получатель.поле` - чтение; `получатель.поле = значение` - присваивание
(тип должен совпадать точно). Сущности - **значения**, не ссылки:
присвоить переменной, передать в функцию, вернуть - копия, как структура в
C (исключение - получатель метода, ниже). Присваивание полю ограничено
**одним уровнем** `.` - чтобы заменить поле внутри вложенной сущности,
нужно переприсвоить всю вложенную сущность целиком.

### Видимость

`приватный`/`публичный` перед полем или методом - необязательный модификатор
(без него - публичное). У поля модификатор согласуется по роду и числу с
именем поля (`приватный пароль`, `приватная почта`, `приватное имя`,
`приватные права`); у метода - не согласуется, только форма мужского рода
(метод называется глаголом, у него нет рода). Область действия
`приватный` - сама сущность: доступ из любого её метода, не снаружи (ни из
свободной функции, ни из метода другой сущности).

### Методы и `этот`

Метод объявляется прямо в теле сущности, без ключевого слова - скобки
параметров обязательны даже без параметров. `получатель.метод(...)` -
строгий вызов (естественный вызов метода не реализован). `этот` внутри
тела метода (см. `проверить_пароль`/`войти` выше) - ссылка на объект, у
которого вызван метод; получатель передаётся во внутреннем C **по
указателю**, поэтому мутация поля через `этот.поле = значение` видна
вызывающему коду после возврата из метода:

```
переменная пользователь = новый Пользователь(пароль: "секрет", имя: "Аня")

вывести пользователь.имя           // "Аня"
вывести пользователь.войти("секрет")   // истина
вывести пользователь.войти("неверно")  // ложь

// Ошибка компиляции, если раскомментировать - "пароль" и
// "проверить_пароль" видны только изнутри методов самой сущности:
// вывести пользователь.пароль
// пользователь.проверить_пароль("секрет")
```

## 9. Состояния (typestate)

```
сущность Пользователь
{
    состояние: авторизован

    имеет:
        имя: Строка

    авторизовать()
    {
        этот становится авторизован
    }
}
```

`состояние: <слово1> <слово2> ...` - конечный список названий состояний,
каждое - краткая форма страдательного причастия (`авторизован`,
`подключён`) или действительное причастие известного глагола (`вошедший`
- от `войти`). Для каждого слова компилятор синтезирует **производный
тип**, согласованный по роду с самой сущностью: `авторизован` при
`Пользователь` (муж. род) даёт `АвторизованныйПользователь`; при `Система`
(жен. род) - `АвторизованнаяСистема`. Производный тип используется везде,
где ожидается имя типа (параметр, поле, тип результата) - как обычная
сущность, без своего C-представления.

`<получатель> становится <состояние>` - переход состояния (пока без
падежного согласования).

**Важное текущее ограничение**: проверка только структурная (само
имя состояния объявлено) - компилятор не проверяет, что объект,
переданный в параметр производного типа, действительно прошёл через
`становится`; значение базовой сущности можно передать без вызова
`становится` вообще, и это не ошибка компиляции. Настоящая
flow-sensitive проверка - в планах (см. [docs/ROADMAP.md](ROADMAP.md)).

## 10. Встроенные generic-коллекции

Единственные встроенные generic-шаблоны - коллекции; пользовательских
generic-типов в языке пока нет. Элемент `T` - только встроенный примитив
(`Строка`, `Целое`, `Число`, `Логическое`), не сущность.

### `Список<T>` - динамический массив

```
переменная числа = новый Список<Целое>()
числа.добавить(10)
вывести числа.получить(0)
```

Методы: `добавить(значение: T)`, `получить(индекс: Целое): T`,
`установить(индекс: Целое, значение: T)`, `длина(): Целое`, `пусто():
Логическое`. `получить`/`установить` с индексом вне `[0, длина())` -
аварийное завершение процесса.

`для <имя> в <коллекция>` - цикл по `Список<T>` (только по нему -
`Стопка`/`Очередь` не участвуют): `<имя>` последовательно получает каждый
элемент. `<коллекция>` пишется существительным **в предложном падеже**,
согласованным с предлогом «в» (`для x в списке`, не `для x в список`) -
падежное сопоставление, тем же принципом, что и у аргументов естественного
вызова. Коллекция - только уже объявленная переменная, не произвольное
выражение.

### `Стопка<T>` - стек (LIFO)

`новая Стопка<Целое>()`. Методы: `положить(значение: T)`, `снять(): T`,
`верх(): T`, `длина(): Целое`, `пусто(): Логическое`. `снять`/`верх` на
пустой стопке - аварийное завершение.

### `Очередь<T>` - очередь (FIFO)

`новая Очередь<Целое>()`. Методы: `добавить(значение: T)` (в конец),
`извлечь(): T`, `первый(): T`, `длина(): Целое`, `пусто(): Логическое`.
`извлечь`/`первый` на пустой очереди - аварийное завершение.

## 11. Встроенные функции

Доступны в любой программе без объявления и без `использовать` -
зарезервированные имена, объявить свою функцию с таким именем нельзя.

### 11.1. Математика

`корень(Число): Число`, `степень(Число, Число): Число`, `округлить(Число):
Целое`, `потолок(Число): Целое`, `пол(Число): Целое`, `модуль(Число):
Число`.

### 11.2. Ввод консоли

`прочитать_строку(): Строка` (одна строка стандартного ввода, без
завершающего переноса строки), `прочитать_целое(): Целое`,
`прочитать_число(): Число` (строка, обрезанная по пробелам/табам с краёв,
разобранная целиком как число; неполный разбор - ошибка формата). Конец
ввода или неверный формат - аварийное завершение (в языке пока нет
исключений).

### 11.3. Строки

`содержит(Строка, Строка): Логическое` - есть ли второй аргумент (образец)
где-то внутри первого.

### 11.4. Файловый ввод-вывод

`Файл` - отдельный примитивный тип (непрозрачный дескриптор, без
операторов, как `Строка`).

- `открыть(Строка): Файл` - на чтение.
- `открыть_для_записи(Строка): Файл` - на запись, существующее содержимое
  обрезается.
- `открыть_для_дозаписи(Строка): Файл` - на запись в конец существующего
  содержимого.
- Ошибка открытия любой из трёх - аварийное завершение.
- `прочитать(Файл, Целое): Строка` - не более указанного числа **байт** (не
  до перевода строки и не до конца текстового «символа»); пустая `Строка`
  - конец файла, не ошибка, можно продолжать вызывать и после конца файла.
  Известное ограничение: чтение произвольного байтового куска может
  разрубить многобайтовую UTF-8-последовательность посередине, если файл -
  не ASCII-текст.
- `записать(Файл, Строка)` - записывает строку целиком, без результата.
- `закрыть(Файл)` - без результата.
- `для <строка> в <Файл> { ... }` - потоковое построчное чтение (файл не
  известной заранее длины, в отличие от `Список<T>`): каждая итерация -
  одна строка без завершающего переноса строки, цикл сам завершается на
  конце файла.
- `стандартный_ввод()`/`стандартный_вывод()`/`стандартный_вывод_ошибок()` -
  те же три стандартных потока процесса, тип `Файл`, работают с
  `прочитать`/`записать`/`для X в Y` без отдельного механизма -
  перенаправление (`|`, `>` в шелле) не требует ничего специального со
  стороны Rech-программы.
- `количество_аргументов(): Целое`/`аргумент(Целое): Строка` - аргументы
  командной строки, переданные собранному бинарнику (`argv`, без имени
  программы); индексация с 0, как у `получить` встроенных коллекций.
  `rech test` (раздел 14) не может передать программе свои аргументы - там
  `количество_аргументов()` всегда `0`, `аргумент` любого индекса паникует.
- Путь у `открыть*` - относительно рабочего каталога процесса, не
  каталога, где лежит сам `.rech`-файл.
- Запись/дозапись и построчное чтение поддержаны и интерпретатором
  (`rech test`), не только `rech build`/`rech run`.
- Высокоуровневые обёртки без ручного `открыть`/`закрыть`:
  `прочитать_файл(Строка): Строка` (всё содержимое целиком),
  `записать_в_файл(Строка, Строка)`/`дописать_в_файл(Строка, Строка)`
  (записывают/дописывают вторым аргументом содержимое файла по первому
  аргументу-пути целиком).

Пример - маленькая Unix-утилита поверх стандартных потоков и аргументов
(`examples/основы/mygrep.rech`):

```
функция главная
{
    если количество_аргументов() != 1
    {
        записать(стандартный_вывод_ошибок(), "нужен ровно один аргумент - образец для поиска\n")
        вернуть
    }
    переменная образец = аргумент(0)
    переменная вход = стандартный_ввод()
    для строка в входе
    {
        если содержит(строка, образец)
        {
            записать(стандартный_вывод(), строка)
            записать(стандартный_вывод(), "\n")
        }
    }
}
```

```sh
rech build examples/основы/mygrep.rech
echo "мир" | examples/основы/mygrep мир
printf "привет\nмир\nвсем\n" | examples/основы/mygrep мир > найдено.txt
```

### 11.5. Сетевые примитивы

`Сокет` - отдельный примитивный тип (непрозрачный дескриптор, без
операторов, как `Файл`). Байты через TCP/UDP, не HTTP - HTTP/JSON DSL
(`docs/ROADMAP.md`, Шаг 9) поверх этих примитивов пока не реализован.

- `слушать_tcp(Целое): Сокет` - создаёт TCP-сокет, привязывает к порту на
  всех интерфейсах, начинает прослушивание.
- `принять(Сокет): Сокет` - блокирует до входящего соединения на слушающем
  сокете, возвращает новый подключённый сокет.
- `подключиться_tcp(Строка, Целое): Сокет` - клиентское TCP-соединение.
- `подключиться_udp(Строка, Целое): Сокет` - клиентский UDP с фиксированным
  адресатом (через `connect()` на datagram-сокете) - `отправить`/`получить`
  дальше работают так же, как у TCP. Известное ограничение: только
  UDP-клиент, не полноценный UDP-сервер для произвольных отправителей.
- `отправить(Сокет, Строка)` - отправляет строку целиком.
- `получить(Сокет, Целое): Строка` - не более указанного числа байт (как
  `прочитать` у `Файл`); для TCP пустая `Строка` - удалённая сторона
  закрыла соединение.
- `закрыть_сокет(Сокет)` - работает и со слушающим, и с подключённым
  сокетом.

Минимальный TCP-эхо-сервер и клиент к нему
(`examples/сеть/эхо_сервер.rech`, `examples/сеть/эхо_клиент.rech`):

```
// эхо_сервер.rech
функция главная
{
    переменная слушатель = слушать_tcp(18080)
    переменная соединение = принять(слушатель)
    переменная сообщение = получить(соединение, 1024)
    отправить(соединение, "эхо: " + сообщение)
    закрыть_сокет(соединение)
    закрыть_сокет(слушатель)
}
```

```
// эхо_клиент.rech
функция главная
{
    переменная сокет = подключиться_tcp("127.0.0.1", 18080)
    отправить(сокет, "привет")
    вывести получить(сокет, 1024)
    закрыть_сокет(сокет)
}
```

```sh
rech build examples/сеть/эхо_сервер.rech
rech build examples/сеть/эхо_клиент.rech
./эхо_сервер &
./эхо_клиент
```

### 11.6. HTTP-клиент (`запрос`)

`запрос(Запрос): Ответ` - HTTP-клиент типа curl поверх сетевых примитивов
выше. `Запрос` и `Ответ` - встроенные сущности (как `Файл`/`Сокет` - не
объявляются, доступны без импорта):

- `Запрос`: `метод`, `адрес`, `порт`, `путь`, `заголовки`, `тело` (в этом
  порядке для позиционного конструктора). `заголовки` - одна `Строка`,
  каждый заголовок на своей строке через `"\r\n"`, без завершающего.
- `Ответ`: `код`, `заголовки`, `тело`.

```
// examples/сеть/http_запрос.rech
функция главная
{
    переменная р = новый Запрос("GET", "example.com", 80, "/", "", "")
    переменная о = запрос(р)
    вывести о.код
    вывести о.тело
}
```

Известное ограничение: ответ читается до закрытия соединения сервером
(`Connection: close` в каждом запросе), не по `Content-Length`/chunked -
сервер, отвечающий чанками без закрытия соединения, будет разобран неверно.

## 12. Внешние функции (FFI)

```
внешняя функция strlen как длина_строки(текст: Строка): Целое
```

Объявление сигнатуры уже существующей C-функции без тела: реализация -
сам C-символ (`strlen`). `как <Псевдоним>` переименовывает его в
Rech-facing имя (тот же принцип, что у `использовать ... как ...`, раздел
13) - без него функция доступна под своим C-именем как есть. Rech-facing
имена - snake_case (POSIX-стиль), без camelCase. Тип результата
необязателен - его отсутствие означает `void`.

Ограничения этого среза:

- нет `из библиотеки "..."` - доступны только уже слинкованные libc/libm
  (компилятор линкует их безусловно);
- типы параметров и результата - только `Целое`/`Число`/`Строка`/
  `Логическое` (у сущностей и generic-коллекций нет стабильного C-
  представления, на которое мог бы полагаться сторонний C-код);
- компилятор не видит настоящий заголовок C-функции - он сам пишет
  `extern`-прототип по объявленным в Rech типам и доверяет, что они
  совпадают с настоящей сигнатурой; несовпадение не ловится компиляцией
  (как и в любом другом минимальном FFI - `ctypes` у Python, `extern "C"`
  в C++ без заголовка);
- **не поддерживается интерпретатором** (`rech test`) - явная ошибка
  компиляции; работает только через `rech build`/`rech run` (нет
  механизма динамически вызвать произвольный C-символ без настоящей
  линковки).

## 13. Модули и импорты

```
использовать получить_версию как версия, описание_кода из "утилиты"
```

Импорт конкретных функций и сущностей из другого файла. Список имён - через
запятую; `<путь>` - строковый литерал (строчные буквы, сегменты через `/`,
без расширения `.rech`), разрешается относительно каталога файла, где
написано `использовать`. Каждое импортированное имя доступно под тем же
именем или под псевдонимом после `как` - единственный способ ввести в один
файл два одноимённых импорта одновременно.

Видимость настоящая: файл видит только то, что объявил сам, и то, что явно
импортировал - обращение к любому другому имени из транзитивно
загруженного файла - ошибка компиляции. Импортировать можно только функции
и сущности, не производные типы состояний и не отдельные
generic-инстанциации.

Работает при сборке из одного файла (`rech build/run <файл>`) и в `rech
test`. **Не работает** при сборке из каталога (`rech build <каталог>`) -
там действует более простое правило «весь каталог - одна единица
компиляции» без разграничения видимости; файл с `использовать` в таком
каталоге - явная ошибка компиляции.

## 14. Тестирование

`rech test <файл.rech>|<каталог>` находит и запускает тестовые файлы -
файлы с суффиксом имени `_тест.rech` (обход каталога рекурсивный). Указанный
явно файл запускается независимо от суффикса.

Тестовый файл - обычная программа Rech со своей `главная`, без отдельного
синтаксиса для тестов: проверки выражаются обычным `утверждать`.

```
функция сложить(а: Целое, б: Целое): Целое { вернуть а + б }

функция главная
{
    утверждать сложить(2, 3) == 5
    утверждать сложить(-1, 1) == 0
}
```

Запускается через встроенный интерпретатор (`internal/interp`), не через
системный `cc` - быстрее, но исполняет ту же программу (тот же
промежуточный код), что и настоящая скомпилированная версия. Провал одного
файла не прерывает прогон остальных. Вывод - прогресс точками (`.`/`F`),
список причин провалов, итоговая сводка.

## 15. Интерфейс командной строки

```
rech build [--keep-c] <файл.rech>|<каталог>|-c "<код>"   - собрать бинарник
rech run   [--keep-c] <файл.rech>|<каталог>|-c "<код>"   - собрать и выполнить
rech test  <файл.rech>|<каталог>                          - найти и запустить тесты
rech version                                              - напечатать версию
```

`<каталог>` у `build`/`run` (например, `.`) собирает все `.rech`-файлы
прямо в нём (без подкаталогов) как одну единицу компиляции - неявное
объединение, не система импортов. `-c/--code "<код>"` (как `python -c`)
собирает/запускает код прямо из аргумента командной строки, без файла.
`--keep-c` оставляет сгенерированный `.c`-файл после сборки.

## 16. Константы и перечисления

`константа <имя> = <значение>` - как `переменная`, но повторное
присваивание этому имени (`имя = ...`, `имя++`/`имя--`) - ошибка
компиляции, не времени выполнения:

```
константа порог = 5
```

`перечисление <Имя> { Член1, Член2 = число, ... }` - верхнеуровневое
объявление именованного набора целочисленных значений (наравне с
`функция`/`сущность`). Член без явного `= число` получает значение
"предыдущее + 1" (0 у первого без явного значения):

```
перечисление Приоритет
{
    Низкий,
    Средний = 5,
    Высокий
}

функция главная
{
    если Приоритет.Высокий >= 5
    {
        вывести "высокий приоритет достаточен"
    }
}
```

`Имя.Член` - выражение типа `Целое` (перечисление логически хранится как
`Целое`, не отдельный несовместимый вид значения) - синтаксически
неотличимо от обращения к полю сущности; если в области видимости уже
есть переменная с именем `Имя`, побеждает она (обычное затенение).

Стандартные перечисления доступны без объявления, как встроенные типы
`Файл`/`Сокет`: `HTTPКод` (частые коды состояния HTTP - `ОК`, `НеНайдено`,
`ОшибкаСервера` и т. д. - для сравнения с `запрос(...).код`, раздел 11),
`ДеньНедели` (`Понедельник`...`Воскресенье`, 1-7), `Месяц`
(`Январь`...`Декабрь`, 1-12).

Не реализовано в этом срезе: перечисление как тип параметра/поля (только
его члены как значения), импорт перечисления между файлами через
`использовать` (перечисления сейчас видны только в пределах одного файла
или каталога, собираемого целиком).

Пример - `examples/основы/константы_и_перечисления.rech`.

## 17. Куда дальше

Это руководство описывает язык таким, какой он есть сейчас - рабочий
пайплайн `Rech -> IR -> C -> нативный бинарник` (`internal/semantic` строит
IR, проверяет типы и flow-sensitive переход состояния до генерации кода) с
отдельным интерпретатором для `rech test`. Числа разной ширины и
знаковости, явные касты между типами, типизированные массивы, наследование
и интерфейсы сущностей, исключения, параллелизм и асинхронность,
пользовательские generic-типы, рефлексия, указатели/ссылки, HTTP/JSON DSL и
`служба` (клиент уже есть - раздел 11, `запрос`), инструментарий вокруг
языка (LSP, расширение для редактора уже есть) - в работе или
запланированы. Подробный план по шагам, с обоснованием порядка и открытыми
вопросами дизайна, - [docs/ROADMAP.md](ROADMAP.md).

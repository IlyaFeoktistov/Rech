# Справочник

Описание каждой встроенной функции, типа/сущности и ключевого слова языка,
вместе с назначением каждого параметра - для быстрого поиска ("что делает
`регулярное`?", "что передавать вторым аргументом в `подстрока`?"), не для
последовательного чтения. Учитесь языку по [Руководству](MANUAL.md);
формальные детали синтаксиса - в [Спецификации](SPEC.md).

Параметры builtin-функций у самого компилятора без имён (только тип,
`internal/builtins.Kind`) - имена ниже введены здесь для описания смысла
и НЕ являются частью естественного (падежного) вызова этой функции (тот
работает только для функций/методов, объявленных в самой программе -
раздел 15 Руководства). `[= значение]` после параметра - у него есть
значение по умолчанию, аргумент можно не передавать вовсе.

## Функции

### Математика

#### `корень`

```
корень(x: Действительное): Действительное
```

Квадратный корень `x`. Отрицательный `x` - результат по IEEE 754
(не-число, NaN), не аварийное завершение.

- `x` - число, из которого извлекается корень.

#### `степень`

```
степень(основание: Действительное, показатель: Действительное): Действительное
```

Возведение `основание` в степень `показатель` (`pow`).

- `основание` - число, которое возводится в степень.
- `показатель` - показатель степени (может быть дробным и отрицательным).

#### `округлить` / `потолок` / `пол`

```
округлить(x: Действительное): Целое
потолок(x: Действительное): Целое
пол(x: Действительное): Целое
```

Три способа привести дробное число к целому: `округлить` - до ближайшего
целого, `потолок` - вверх, `пол` - вниз.

- `x` - округляемое число.

#### `модуль`

```
модуль(x: Действительное): Действительное
```

Абсолютное значение `x` (убирает знак).

- `x` - число.

#### `экспонента`

```
экспонента(x: Действительное): Действительное
```

`e` в степени `x` (обратная операция к `логарифм`).

- `x` - показатель степени.

#### Тригонометрия

```
синус(x: Действительное): Действительное
косинус(x: Действительное): Действительное
тангенс(x: Действительное): Действительное
арксинус(x: Действительное): Действительное
арккосинус(x: Действительное): Действительное
арктангенс(x: Действительное): Действительное
арктангенс2(y: Действительное, x: Действительное): Действительное
```

`синус`/`косинус`/`тангенс` принимают угол **в радианах**;
`арксинус`/`арккосинус`/`арктангенс` возвращают угол **в радианах**.
`арктангенс2(y, x)` (`atan2`) - угол вектора `(x, y)` с учётом знаков
ОБОИХ аргументов (в отличие от `арктангенс(y/x)`, которая теряет
информацию о четверти).

- `x` / `y` - координаты или значение угла, в зависимости от функции.

#### Логарифмы

```
логарифм(x: Действительное): Действительное
логарифм2(x: Действительное): Действительное
логарифм10(x: Действительное): Действительное
```

Натуральный логарифм (по основанию `e`), по основанию 2, по основанию 10.

- `x` - число, от которого берётся логарифм (`x <= 0` - результат по
  IEEE 754, не аварийное завершение).

#### `минимум` / `максимум`

```
минимум(a: Действительное, b: Действительное): Действительное
максимум(a: Действительное, b: Действительное): Действительное
```

- `a`, `b` - два сравниваемых числа.

#### `пи`

```
пи(): Действительное
```

Число π (3.14159…). Без параметров.

#### Целочисленная арифметика

```
абсолютное_значение_целого(x: Целое): Целое
знак(x: Действительное): Целое
наименьшее(a: Целое, b: Целое): Целое
наибольшее(a: Целое, b: Целое): Целое
ограничить(значение: Действительное, минимум: Действительное, максимум: Действительное): Действительное
остаток(x: Действительное, y: Действительное): Действительное
степень_целого(основание: Целое, показатель: Целое): Целое
```

`наименьшее`/`наибольшее` - целочисленные версии `минимум`/`максимум` выше:
не теряют точность у значений за пределами 53-битной mantissa
`Действительное`. `знак` - `-1`/`0`/`1`. `ограничить` - зажимает `значение`
в `[минимум, максимум]`. `остаток` - остаток от деления с плавающей точкой
(`fmod`; `%` определён только для целых типов). `степень_целого` -
целочисленное возведение в степень; отрицательный `показатель` даёт `0`
(нет содержательного целого результата).

#### Гиперболические функции

```
синус_гиперболический(x: Действительное): Действительное
косинус_гиперболический(x: Действительное): Действительное
тангенс_гиперболический(x: Действительное): Действительное
арксинус_гиперболический(x: Действительное): Действительное
арккосинус_гиперболический(x: Действительное): Действительное
арктангенс_гиперболический(x: Действительное): Действительное
экспонента_минус_один(x: Действительное): Действительное
логарифм_плюс_один(x: Действительное): Действительное
гипотенуза(x: Действительное, y: Действительное): Действительное
```

`экспонента_минус_один` (`expm1`) точнее `экспонента(x) - 1` при `x`,
близком к нулю; `логарифм_плюс_один` (`log1p`) точнее `логарифм(1 + x)`
при `x`, близком к нулю. `гипотенуза` - `√(x² + y²)` без промежуточного
переполнения.

#### Бесконечность и NaN

```
Действительное::БЕСКОНЕЧНОСТЬ, Действительное::НЕ_ЧИСЛО
Дробное::БЕСКОНЕЧНОСТЬ, Дробное::НЕ_ЧИСЛО
x.бесконечно(): Логическое     // бесконечно(x: Действительное): Логическое
x.не_число(): Логическое       // не_число(x: Действительное): Логическое
x.конечно(): Логическое        // конечно(x: Действительное): Логическое
```

`x` - `Действительное` или `Дробное`. NaN не равен даже самому себе, поэтому
`x == Действительное::НЕ_ЧИСЛО` всегда `ложь` - проверяйте `x.не_число()`.
`конечно` - истина для обычного числа (не бесконечность и не NaN).

### Системы счисления

Литералы `0x.../0o.../0b...` - см. [раздел про литералы в SPEC.md](SPEC.md).
Обратное преобразование число <-> строка - отдельные функции (не каст).

#### `целое_в_hex` / `целое_из_hex`

```
целое_в_hex(n: Целое): Строка
целое_из_hex(s: Строка): Целое
```

`целое_в_hex` - битовый паттерн `n` (`uint64(n)`, не величина - `целое_в_hex(-1)`
даёт `"0xffffffffffffffff"`) как `"0x..."`, строчными цифрами, без отступа
нулями. `целое_из_hex` - обратное: префикс `"0x"`/`"0X"` необязателен
(`"FF"` и `"0xFF"` равнозначны), `ОшибкаРазбора` при недопустимом символе.

#### `целое_в_oct` / `целое_из_oct`

```
целое_в_oct(n: Целое): Строка
целое_из_oct(s: Строка): Целое
```

То же самое для восьмеричной формы (`"0o..."`).

#### `целое_в_bin` / `целое_из_bin`

```
целое_в_bin(n: Целое): Строка
целое_из_bin(s: Строка): Целое
```

То же самое для двоичной формы (`"0b..."`).

### Случайные числа

Криптографически стойкий источник (`arc4random`/`crypto/rand`), не
воспроизводимый генератор с seed - каждый вызов даёт новое, непредсказуемое
значение.

#### `случайное`

```
случайное(): Действительное
```

Случайное дробное число в `[0.0, 1.0)`. Без параметров.

#### `случайное_целое`

```
случайное_целое(от: Целое, до: Целое): Целое
```

Случайное целое в `[от, до]`, оба конца включительно.

- `от` - нижняя граница диапазона (включительно).
- `до` - верхняя граница диапазона (включительно). `от > до` - аварийное
  завершение процесса (пустой диапазон - неоднозначен, не выбирается
  молча).

### Строки

Каждую функцию этого раздела можно вызвать и как метод строки - строка
становится первым аргументом: `т.длина()` (`длина_строки`), `т.подстрока(н, д)`,
`т.позиция(образец)` (`позиция_в_строке`), `т.обрезать()`, `т.содержит(образец)`,
`т.разбить(разделитель)`, `т.регулярное(шаблон)`, `т.в_верхний_регистр()`,
`т.в_нижний_регистр()`, `т.заменить(образец, замена)`, `т.начинается_с(префикс)`,
`т.заканчивается_на(суффикс)`.

#### `длина_строки`

```
длина_строки(строка: Строка): Целое
```

- `строка` - строка, чья длина измеряется в кодовых точках Unicode (не
  байтах UTF-8) - `длина_строки("привет")` == 6, а не число байт.

#### `подстрока`

```
подстрока(строка: Строка, начало: Целое, длина: Целое): Строка
```

Вырезает часть строки.

- `строка` - исходная строка.
- `начало` - индекс первого включаемого символа, в кодовых точках, с 0.
- `длина` - сколько символов включить в результат (не индекс конца!).
  `начало`/`длина` отрицательны, или диапазон выходит за конец строки -
  аварийное завершение.

#### `позиция_в_строке`

```
позиция_в_строке(строка: Строка, образец: Строка): Целое
```

- `строка` - строка, в которой ищем.
- `образец` - искомая подстрока (буквальное совпадение, не regex).

Возвращает индекс первого вхождения (в кодовых точках), `-1` - образец не
найден.

#### `обрезать`

```
обрезать(текст: Строка): Строка
```

- `текст` - строка, у которой обрезаются края.

Убирает пробелы, табы (`\t`) и переносы строк (`\n`/`\r`) с ОБОИХ концов
строки - тот же набор символов, что и в примерах, писавших это вручную до
появления этой функции (`examples/бд/orm_легковесный.rech`).

#### `в_верхний_регистр` / `в_нижний_регистр`

```
в_верхний_регистр(текст: Строка): Строка
в_нижний_регистр(текст: Строка): Строка
```

- `текст` - исходная строка.

Новая строка, где каждая буква переведена в заглавную/строчную - для любого
алфавита (`"ёжик".в_верхний_регистр()` - `"ЁЖИК"`, `"Ωμέγα"` - `"ΩΜΈΓΑ"`).
Буква без односимвольной пары (`ß`) остаётся как есть.

#### `заменить`

```
заменить(текст: Строка, образец: Строка, замена: Строка): Строка
```

- `текст` - исходная строка; `образец` - что искать (буквально, не regex);
  `замена` - чем заменить.

Новая строка, где заменены ВСЕ вхождения образца. Пустой образец - паника.

#### `начинается_с` / `заканчивается_на`

```
начинается_с(текст: Строка, префикс: Строка): Логическое
заканчивается_на(текст: Строка, суффикс: Строка): Логическое
```

`истина`, если строка начинается префиксом/заканчивается суффиксом (пустой
префикс/суффикс - всегда `истина`).

#### `содержит`

```
содержит(строка: Строка, образец: Строка): Логическое
```

- `строка` - строка, в которой ищем.
- `образец` - искомая подстрока.

`истина`, если `образец` встречается где-то внутри `строка`.

#### `разбить`

```
разбить(строка: Строка, разделитель: Строка): Список<Строка>
```

- `строка` - строка, которую нужно разбить на части.
- `разделитель` - буквальная подстрока-граница (не regex). Пустая строка -
  аварийное завершение (неоднозначно: "по чему" разбивать).

#### `регулярное`

```
регулярное(строка: Строка, шаблон: Строка): Список<Совпадение>
```

- `строка` - строка, по которой ищутся совпадения.
- `шаблон` - regex-шаблон. POSIX ERE (`regcomp`) у скомпилированной
  программы, RE2 у `rech test`/интерпретатора - `\d`/`\D`/`\w`/`\W`
  переведены так, чтобы вести себя одинаково в обоих (включая кириллицу в
  `\w`). Non-capturing группы `(?:...)` и lookahead/lookbehind не
  поддерживаются - некорректный шаблон аварийно завершает процесс с
  диагностикой движка.

Возвращает все непересекающиеся вхождения, см. [`Совпадение`](#Совпадение)
ниже.

!!! warning "`Строка` - только текст"
    `Строка` - всегда валидный UTF-8 без нулевого байта. Невалидные байты и
    нулевой байт из внешних данных (файл, сокет, тело HTTP-запроса,
    `строка_из_байт`) становятся символом `�` (U+FFFD). Для двоичных данных -
    `Список<Байт>`.

### Ввод консоли

Без параметров - читают из стандартного ввода процесса.

```
прочитать_строку(): Строка
прочитать_целое(): Целое
прочитать_число(): Действительное
```

`прочитать_строку` - одна строка, без завершающего переноса строки.
`прочитать_целое`/`прочитать_число` - строка ввода, обрезанная по пробелам
с краёв и разобранная ЦЕЛИКОМ как число; неполный разбор - `ОшибкаРазбора`,
конец ввода - `ОшибкаФайла`.

### Файлы

!!! note "Метод-стиль"
    `файл.прочитать(...)`/`файл.записать(...)`/`файл.закрыть()`/
    `файл.прочитать_байты(...)`/`файл.записать_байты(...)`/
    `файл.можно_прочитать_байт(...)` - то же самое, что одноимённые
    свободные функции ниже, получатель становится первым аргументом. Три
    `открыть*`/три обёртки `прочитать_файл`/`записать_в_файл`/
    `дописать_в_файл` остаются только свободными функциями (конструкторы/
    принимают путь, не `Файл`).

#### `открыть` / `открыть_для_записи` / `открыть_для_дозаписи`

```
открыть(путь: Строка): Файл
открыть_для_записи(путь: Строка): Файл
открыть_для_дозаписи(путь: Строка): Файл
```

Три отдельные функции, не одна с параметром-режимом.

- `путь` - путь к файлу: относительный (от рабочего каталога процесса) или
  полный. Полный путь можно собрать через `текущий_каталог()` ниже, если
  относительный ненадёжен (например, программа сама меняет рабочий
  каталог).

`открыть` - на чтение (файл должен существовать). `открыть_для_записи` -
на запись, существующее содержимое ОБРЕЗАЕТСЯ. `открыть_для_дозаписи` - на
запись в конец существующего содержимого. Ошибка открытия любой из трёх -
`ОшибкаФайла`.

#### `текущий_каталог`

```
текущий_каталог(): Строка
```

Полный (абсолютный) путь рабочего каталога процесса. Не путать с
каталогом, где лежит сам `.rech`-файл - такого понятия в рантайме нет
вовсе, `путь` у `открыть*` резолвится ОС относительно рабочего каталога
процесса, не места на диске, где лежит исходник.

#### `прочитать`

```
прочитать(файл: Файл, максимум: Целое): Строка
```

- `файл` - открытый дескриптор (результат `открыть*`/`стандартный_ввод`).
- `максимум` - не более скольких БАЙТ прочитать (не символов, не строк).

Кусок кончается целым символом: байты символа, не поместившегося целиком,
достаются следующему чтению этого файла; если первый же символ длиннее
`максимум`, он возвращается целиком. Пустая строка в результате означает
конец файла, не ошибку - можно продолжать вызывать и дальше.

#### `записать`

```
записать(файл: Файл, содержимое: Строка)
```

- `файл` - дескриптор, открытый на запись.
- `содержимое` - строка, записываемая целиком (без результата).

#### `закрыть`

```
закрыть(файл: Файл)
```

- `файл` - закрываемый дескриптор.

#### `прочитать_файл` / `записать_в_файл` / `дописать_в_файл`

```
прочитать_файл(путь: Строка): Строка
записать_в_файл(путь: Строка, содержимое: Строка)
дописать_в_файл(путь: Строка, содержимое: Строка)
```

Высокоуровневые обёртки без ручного открыть/закрыть - типичный сценарий
"прочитать/записать файл целиком".

- `путь` - путь к файлу.
- `содержимое` - (только у `записать_в_файл`/`дописать_в_файл`) строка,
  записываемая целиком. `записать_в_файл` обрезает существующее
  содержимое, `дописать_в_файл` добавляет в конец.

#### Стандартные потоки

```
стандартный_ввод(): Файл
стандартный_вывод(): Файл
стандартный_вывод_ошибок(): Файл
```

Без параметров - тот же тип `Файл`, что и у обычных открытых файлов,
работают с `прочитать`/`записать`/`для X в Y` точно так же.

### Аргументы командной строки

Встроенных функций нет - аргументы приходят параметром точки входа:

```
публичная функция главная(аргументы: Список<Строка>): Целое
```

`аргументы` - без имени программы, `аргументы.первый()` - первый аргумент.
Результат `: Целое` - код завершения процесса (без него - 0). В `rech test`
(интерпретатор) список пуст.

### Текущая ОС

```
текущая_ос(): Целое
```

Платформа, для которой собрана программа - `ОС.Linux`/`ОС.Windows`/
`ОС.MacOS`. У `rech build`/`rech run` (cbackend) - целевая платформа
СБОРКИ (известна уже во время компиляции, не запрос к реальной ОС в
рантайме); у `rech test` (интерпретатор) - настоящий хост, на котором он
запущен.

### Условная компиляция по платформе

`текущая_ос()` проверяется в рантайме - для объявлений (`внешняя функция`
и подобные, [SPEC.md, раздел 12](SPEC.md#12-внешние-функции-ffi)), которые
должны отличаться от платформы к платформе целиком, нужна условная
компиляция - исключённый код не доходит до компилятора вовсе, не остаётся
как обычный "мёртвый код":

```
#если ОС.Windows {
    внешняя функция CreateWindowExW как создать_окно(...): Целое
} #иначе если ОС.MacOS {
    внешняя функция NSCreateWindow как создать_окно(...): Целое
} #иначе {
    внешняя функция XCreateWindow как создать_окно(...): Целое
}
```

Тот же результат на уровне целого файла - `путь_windows.rech`/
`путь_linux.rech`/`путь_macos.rech` рядом с `путь.rech`: `использовать ...
из "путь"` выбирает файл под текущую платформу сборки сам. Библиотека для
линковки тоже может быть разной по платформе -
`сборка.библиотеки_windows`/`_linux`/`_macos` в `.rechproj`. Подробности -
[SPEC.md, раздел 27](SPEC.md#27-условная-компиляция-по-платформе).

### Процесс

```
спать_мс(миллисекунды: Целое)
выйти(код: Целое)
```

`спать_мс` - приостанавливает ТЕКУЩИЙ поток (главный или "запустить"-поток -
тот, что её вызвал) на указанное число миллисекунд; `миллисекунды <= 0` -
не спит вовсе (не ошибка).

`выйти` - немедленно завершает ВЕСЬ процесс с указанным кодом возврата, из
любой глубины вызовов, минуя `окончательно`/`поймать` объемлющих
`попытаться` (тот же принцип, что `exit()` в C) - НЕ то же самое, что
`вернуть` из `главная`, которая не умеет отдавать код возврата вообще.

### Сеть

!!! note "Метод-стиль"
    `сокет.отправить(...)`/`сокет.получить(...)`/`сокет.закрыть()`/
    `сокет.установить_таймаут(...)`/`сокет.принять()`/
    `сокет.получить_от(...)`/`сокет.отправить_в(...)`/
    `сокет.принять_http(...)`/`сокет.отправить_http_ответ(...)`/
    `сокет.принять_http_байты(...)`/`сокет.отправить_http_ответ_байты(...)`/
    `сокет.принять_http2_сессию()` - то же самое, что одноимённые (для
    HTTP/2 - без префикса `http2_`) свободные функции ниже, получатель
    становится первым аргументом. `сетевой_узел` остаётся только свободной
    функцией (конструктор).

#### `сетевой_узел`

```
сетевой_узел(режим: Целое, хост: Строка, порт: Целое): Сокет
```

Единая точка входа для TCP/UDP - слушающий или клиентский узел решает
пустой/непустой `хост`, не отдельные функции.

- `режим` - `СетевойПротокол.TCP` или `СетевойПротокол.UDP` (курируемое
  перечисление - другое числовое значение мимо этих двух членов - авария в
  рантайме, достижимо только явным целочисленным литералом).
- `хост` - `""` - слушающий узел (`bind`+`listen` для TCP, `bind` для
  UDP); непустой хост (например `"127.0.0.1"` или доменное имя) -
  клиентский узел (`connect`).
- `порт` - номер порта. У слушающего узла - порт для приёма соединений; у
  клиентского - порт сервера, к которому подключаемся.

#### `отправить` / `получить`

```
отправить(сокет: Сокет, данные: Строка)
получить(сокет: Сокет, максимум: Целое): Строка
```

Для УЖЕ подключённого сокета (клиентский TCP/UDP или результат
`принять`) - собеседник зафиксирован самим соединением.

- `сокет` - подключённый сокет.
- `данные` - (у `отправить`) байты строки для отправки.
- `максимум` - (у `получить`) не более скольких байт прочитать; кусок
  кончается целым символом, как у `прочитать` (остаток - следующему
  `получить` этого сокета).

#### `закрыть_сокет`

```
закрыть_сокет(сокет: Сокет)
```

- `сокет` - закрываемый сокет (слушающий или подключённый).

#### `установить_таймаут`

```
установить_таймаут(сокет: Сокет, миллисекунды: Целое)
```

Ограничивает, сколько `получить`/`принять`/`принять_http` готовы
блокироваться на этом сокете, прежде чем вернуть ошибку/`Ничто`.

- `сокет` - сокет, для которого задаётся таймаут.
- `миллисекунды` - максимальное время ожидания.

#### `получить_от` / `отправить_в`

```
получить_от(сокет: Сокет, максимум: Целое): Дейтаграмма
отправить_в(сокет: Сокет, данные: Строка, адрес: Строка, порт: Целое)
```

Для UDP-узла БЕЗ хоста (слушающего, отвечающего произвольным
отправителям) - адрес собеседника не зафиксирован, поэтому передаётся
явно (в отличие от `отправить`/`получить` выше).

- `сокет` - слушающий UDP-узел.
- `максимум` - (у `получить_от`) не более скольких байт прочитать.
- `данные` - (у `отправить_в`) отправляемые байты.
- `адрес`, `порт` - (у `отправить_в`) куда отправить сообщение.

#### `принять`

```
принять(сокет: Сокет): ?Сокет
```

- `сокет` - слушающий TCP-узел.

Принимает одно входящее соединение, возвращает НОВЫЙ `Сокет` для этого
клиента. `Ничто` - истёк таймаут (см. `установить_таймаут`), не ошибка.

#### `запрошена_остановка`

```
запрошена_остановка(): Логическое
```

Без параметров. Истина после получения процессом SIGINT/SIGTERM (на
Windows - Ctrl+C), а у программы `сборка.тип: служба` на Windows - и после
команды "Остановить"/завершения системы от диспетчера служб. Только
взводит флаг, сама не прерывает выполнение (типичный сценарий graceful
shutdown - выйти из цикла приёма соединений по этому флагу).

#### `получен_сигнал`

```
получен_сигнал(сигнал: СигналОС): Логическое
```

- `сигнал` - см. [`СигналОС`](#СигналОС).

Тот же принцип, что и `запрошена_остановка`, для ЛЮБОГО именованного
POSIX-сигнала - истина после того, как процесс получил его хотя бы раз,
флаг взводится навсегда, не сбрасывается. `СигналОС.SIGKILL`/
`СигналОС.SIGSTOP` - паника, POSIX не даёт перехватить ни один из двух ни
при каких условиях. Windows - взводится только для `SIGINT`/`SIGABRT`/
`SIGTERM` (единственные, что определяет MinGW CRT), для остальных имён
флаг никогда не взводится на этой платформе.

`SIGILL`/`SIGTRAP`/`SIGBUS`/`SIGFPE`/`SIGSEGV`/`SIGSYS` - сигналы
аппаратных ошибок программы, не события "снаружи" - регистрируются, но
возврат из обработчика возобновляет выполнение прямо с ошибочной
инструкции (на практике обычно немедленный повторный сигнал). Надёжно
ловятся, только если посланы другим процессом (`отправить_сигнал`), не
когда вызваны настоящей аппаратной ошибкой самой программы.

#### `отправить_сигнал`

```
отправить_сигнал(pid: Целое, сигнал: СигналОС)
```

- `pid` - идентификатор процесса-адресата.
- `сигнал` - см. [`СигналОС`](#СигналОС).

Обратная сторона `получен_сигнал` - отправляет именованный сигнал другому
процессу по его `pid` (`kill(2)`). В отличие от приёма,
`СигналОС.SIGKILL`/`СигналОС.SIGSTOP` здесь разрешены - отправить их
другому процессу можно всегда, POSIX запрещает только их перехват самим
адресатом. `ОшибкаПроцесса` - только если сама отправка не удалась (нет такого
`pid`, недостаточно прав). Windows - `SIGINT` через
`GenerateConsoleCtrlEvent`, `SIGKILL`/`SIGTERM` через `TerminateProcess`,
остальные имена - `ОшибкаПроцесса` (аналога нет).

#### `запустить_процесс`

```
запустить_процесс(команда: Строка, аргументы: Список<Строка>): Процесс
```

- `команда` - имя программы (резолвится через `PATH`, как обычный запуск в
  терминале).
- `аргументы` - список аргументов командной строки.

Неблокирующий запуск ВНЕШНЕГО процесса БЕЗ системной оболочки (`execvp`/
`CreateProcess` напрямую - без пайпов/`&&`/подстановок, как в скрипте, не
в интерактивном шелле). Возвращает сразу, не дожидаясь завершения -
сущность `Процесс` с единственным полем `pid: Целое`, годным для уже
существующего `отправить_сигнал` (например, `отправить_сигнал(п.pid,
СигналОС.SIGTERM)` - завершить запущенный процесс). `ОшибкаПроцесса`, если
программу не удалось запустить (не найдена в `PATH`, недостаточно прав).

Дочерний процесс наследует стандартные потоки самой программы (виден в
том же терминале) - для перехвата вывода см. `выполнить_команду` ниже.

#### `дождаться_процесса`

```
дождаться_процесса(процесс: Процесс): Целое
```

- `процесс` - результат РАНЕЕ вызванного `запустить_процесс`.

Блокируется до завершения процесса, возвращает код возврата (обычное
завершение) или `128 + номер сигнала` (завершён сигналом - то же
соглашение, что у `$?` в POSIX-оболочке после `kill`). Обязателен для
каждого процесса, запущенного через `запустить_процесс` - без него
завершившийся потомок остаётся зомби вплоть до выхода самой программы
(POSIX). `ОшибкаПроцесса` - неверный `pid` или процесс уже был дождан ранее.

!!! note "Метод-стиль"
    `процесс.дождаться_завершения()` - то же самое, получатель становится
    аргументом. Не голое "дождаться" - слово уже зарезервировано
    (async/await-синтаксис, `дождаться <асинхронная функция>()`).

#### `выполнить_команду`

```
выполнить_команду(команда: Строка, каталог: Строка = ""): РезультатКоманды
```

- `команда` - командная строка целиком, как в терминале (пайпы/`&&`/
  подстановка - работают, разбирает системная оболочка).
- `каталог` - рабочий каталог ИМЕННО этой команды; пустая строка (значение
  по умолчанию) - унаследовать текущий рабочий каталог программы, не
  менять его.

Блокирующий запуск ЧЕРЕЗ системную оболочку (`sh -c` на POSIX, `cmd /C` на
Windows) - в отличие от `запустить_процесс`, понимает синтаксис шелла.
Возвращает сущность `РезультатКоманды`:

- `вывод: Строка` - стандартный вывод команды.
- `ошибка: Строка` - стандартный вывод ошибок, ОТДЕЛЬНО от `вывод`.
- `код_возврата: Целое` - код возврата (`128 + сигнал`, если команда убита
  сигналом).

`ОшибкаПроцесса` - только если саму команду (точнее, оболочку) не удалось
запустить; ненулевой код возврата ЗАПУЩЕННОЙ команды - обычный результат, не ошибка
(`выполнить_команду("git status").код_возврата` вне репозитория - просто
не ноль, без необходимости в `попытаться`).

#### `подключиться_к_процессу`

```
подключиться_к_процессу(pid: Целое): Процесс
```

- `pid` - идентификатор уже запущенного процесса (не обязательно
  запущенного этой же программой).

Мини-отладчик - подключается к уже запущенному процессу по `pid`,
ОСТАНАВЛИВАЯ его, как это делает настоящий отладчик.

`ОшибкаПроцесса` - нет процесса с таким `pid`, недостаточно прав, либо
текущая платформа не поддерживает эту операцию вовсе (не Linux/Windows).

#### `отключиться_от_процесса`

```
отключиться_от_процесса(процесс: Процесс)
```

- `процесс` - результат РАНЕЕ вызванного `подключиться_к_процессу`.

Отключается от процесса, возобновляя его выполнение.

!!! note "Метод-стиль"
    `процесс.отключиться()` - то же самое, получатель становится
    аргументом.

#### `прочитать_память`

```
прочитать_память(процесс: Процесс, адрес: Целое, размер: Целое): Список<Байт>
```

- `процесс` - результат `подключиться_к_процессу` (или `запустить_процесс`
  - оба возвращают одну и ту же сущность).
- `адрес` - абсолютный адрес в адресном пространстве процесса.
- `размер` - количество байт для чтения.

Читает `размер` байт начиная с `адреса`. Никакого знания о том, что лежит
по адресу (структура/строка/число) - дело вызывающей программы. `ОшибкаПроцесса` -
адрес вне отображённых страниц, размер не положителен, или процесс
завершился между подключением и чтением.

!!! note "Метод-стиль"
    `процесс.прочитать(адрес, размер)` - то же самое, получатель
    становится первым аргументом.

#### `записать_память`

```
записать_память(процесс: Процесс, адрес: Целое, байты: Список<Байт>)
```

Пишет `байты` начиная с `адреса`. Те же причины `ОшибкаПроцесса`, что и у
`прочитать_память`, либо страница доступна только для чтения.

!!! note "Метод-стиль"
    `процесс.записать(адрес, байты)` - то же самое, получатель становится
    первым аргументом.

#### `найти_байты`

```
найти_байты(процесс: Процесс, шаблон: Список<Байт>): Список<Целое>
```

- `процесс` - результат `подключиться_к_процессу` (или `запустить_процесс`).
- `шаблон` - искомая байтовая последовательность (непустая).

Сканирует ВСЮ читаемую память процесса и возвращает адреса ВСЕХ вхождений
`шаблона`. Паника - только пустой `шаблон`.

!!! note "Метод-стиль"
    `процесс.найти(шаблон)` - то же самое, получатель становится первым
    аргументом.

#### `регистры_процесса`

```
регистры_процесса(процесс: Процесс): Регистры
```

Читает текущие регистры остановленного процесса - сущность `Регистры`
(общие регистры amd64: `rax`/`rbx`/`rcx`/`rdx`/`rsi`/`rdi`/`rbp`/`rsp`/
`rip`/`r8`..`r15`/`eflags`). Другие архитектуры (arm64 и т. д.) не
поддержаны.

!!! note "Метод-стиль"
    `процесс.регистры()` - то же самое, получатель становится аргументом.

#### `установить_регистры_процесса`

```
установить_регистры_процесса(процесс: Процесс, регистры: Регистры)
```

Записывает регистры обратно (типичный мотив - поменять `rip`, чтобы
перенаправить выполнение). Читает текущие регистры перед записью и правит
только известные поля - не трогает сегментные/отладочные регистры/
состояние FPU, которых нет в `Регистры`.

!!! note "Метод-стиль"
    `процесс.установить_регистры(р)` - то же самое, получатель становится
    первым аргументом.

#### `установить_точку_останова`

```
установить_точку_останова(процесс: Процесс, адрес: Целое)
```

Ставит программную точку останова (инструкция `int3`) по адресу,
запоминая исходный байт для восстановления.

!!! note "Метод-стиль"
    `процесс.точка_останова(адрес)` - то же самое, получатель становится
    первым аргументом.

#### `снять_точку_останова`

```
снять_точку_останова(процесс: Процесс, адрес: Целое)
```

Восстанавливает исходный байт по уже поставленной точке останова.

!!! note "Метод-стиль"
    `процесс.снять_точку_останова(адрес)` - то же самое, получатель
    становится первым аргументом.

#### `возобновить_процесс`

```
возобновить_процесс(процесс: Процесс): Целое
```

Продолжает выполнение до следующей остановки (точка останова/завершение
процесса), возвращает адрес остановки (`-1` - процесс завершился). Если
текущий `rip` стоит ровно на уже поставленной точке останова, автоматически
выполняет ОДНУ настоящую инструкцию через неё, прежде чем по-настоящему
продолжить - вызывающему коду не нужно знать про эту механику.

!!! note "Метод-стиль"
    `процесс.возобновить()` - то же самое, получатель становится
    аргументом.

#### `установить_сырой_режим`

```
установить_сырой_режим(включить: Логическое)
```

Переключает терминал (stdin) в сырой режим (истина) - посимвольное чтение
без ожидания Enter и без echo - или обратно в обычный, построчный (ложь).
`прочитать(Файл, Целое)` на `стандартный_ввод()` уже читает побайтово - не
хватало только этого переключения. Исходный режим запоминается один раз,
при первом включении - "выключить" возвращает его как было.

#### `ширина_терминала`/`высота_терминала`

```
ширина_терминала(): Целое
высота_терминала(): Целое
```

Без параметров. Размер терминала в символах (столбцы/строки); 80x24 -
откат, если размер не удалось узнать (не терминал вовсе - перенаправлен в
файл/канал).

#### `можно_прочитать_байт`

```
можно_прочитать_байт(файл: Файл, миллисекунды: Целое): Логическое
```

- `файл` - любой открытый `Файл` (не только терминал).
- `миллисекунды` - таймаут ожидания; отрицательное значение - ждать
  бесконечно.

Истина, если можно прочитать хотя бы один байт без блокировки в течение
таймаута - ложь, если он истёк. Мотивирующий сценарий - TUI: отличить
одинокий Escape от начала ANSI-последовательности стрелки/F-клавиши без
риска зависнуть в блокирующем `прочитать` (см.
`examples/консоль/клавиши.rech`). Требует отключённой буферизации stdin,
которую сама включает `установить_сырой_режим(истина)`.

#### `прочитать_код_клавиши`

```
прочитать_код_клавиши(миллисекунды: Целое): КодКлавиши
```

- `миллисекунды` - таймаут ожидания нажатия; отрицательное значение - ждать
  бесконечно.

Физический код нажатой клавиши (см. [`КодКлавиши`](#КодКлавиши)) - НЕ
зависит от раскладки, в отличие от байтов, которые видит терминал через
`прочитать(стандартный_ввод(), ...)` ("w"/"ц" на ЙЦУКЕН - разные байты
одной и той же физической клавиши). `-1`, если за таймаут ничего не
нажали, ИЛИ если раскладко-независимое чтение недоступно вовсе на этой
платформе/в этой сессии - НЕ паника.

Реализация платформо-зависима:

- **Linux** - `/dev/input/eventN` (evdev). Требует прав на устройство -
  обычно их даёт `systemd-logind` активной сессии рабочего стола
  (автоматический ACL "uaccess"), поэтому на настоящем desktop-логине
  чаще всего работает без явной настройки - но НЕ работает там, где
  такой сессии нет вовсе (SSH, WSL2, большинство контейнеров/CI) - там
  всегда `-1`.
- **Windows** - `ReadConsoleInput`/`wVirtualKeyCode` - не требует прав
  администратора.
- **macOS** - не реализовано (отдельная задача, требует IOKit HID/
  `NSEvent.keyCode`) - всегда `-1`.

Пример - `examples/консоль/демо_код_клавиши.rech`. Мотивирующий сценарий -
геймплейный код вида WASD/стрелки, для которого важна ПОЗИЦИЯ клавиши, не
символ на ней (`examples/проекты/змейка/исходники/ввод/
раскладконезависимый_ввод.rech` - альтернатива байтовому вводу той же
игры).

#### `rgbцвет_из_hex`/`rgbцвет_в_hex`

```
rgbцвет_из_hex(hex: Строка): RGBЦвет
rgbцвет_в_hex(цвет: RGBЦвет): Строка
```

- `hex` - `"#RRGGBB"` или `"RRGGBB"` (символ `"#"` необязателен).

Обратные друг другу - `RGBЦвет` (см. [`RGBЦвет`](#RGBЦвет)) в/из
шестнадцатеричной строки. Неверный формат (не 6 шестнадцатеричных цифр
после необязательного `"#"`) - `ОшибкаРазбора`.

#### `дождаться_всех_задач`

```
дождаться_всех_задач(миллисекунды: Целое): Логическое
```

- `миллисекунды` - таймаут ожидания. `<= 0` - проверить немедленно, не
  ждать вовсе.

Блокируется, пока не завершатся ВСЕ когда-либо запущенные (`запустить`)
задачи программы (включая те, чей результат никогда не забирался через
`дождаться`), или не истечёт таймаут. Истина - всё завершилось, ложь -
истёк таймаут.

#### `слушать_tcp_защищённо`

```
слушать_tcp_защищённо(порт: Целое, файл_сертификата: Строка, файл_ключа: Строка): Сокет
```

Только серверная сторона - `принять` на результате сразу выполняет
TLS-рукопожатие, дальше обычные `отправить`/`получить`/`закрыть_сокет`.

- `порт` - порт, на котором слушать.
- `файл_сертификата` - путь к файлу сертификата (PEM).
- `файл_ключа` - путь к файлу приватного ключа (PEM).

### HTTP

#### `запрос`

```
запрос(запрос: Запрос): Ответ
```

Выполняет HTTP-запрос (клиент).

- `запрос` - сущность [`Запрос`](#Запрос) с заполненными полями
  метод/адрес/порт/путь/заголовки/тело.

#### `принять_http`

```
принять_http(сокет: Сокет): Запрос
```

- `сокет` - результат `принять` на TCP-узле сервера.

Читает и разбирает один HTTP-запрос целиком.

#### `отправить_http_ответ`

```
отправить_http_ответ(сокет: Сокет, ответ: Ответ)
```

- `сокет` - сокет клиента (тот же, что был у `принять_http`).
- `ответ` - сущность [`Ответ`](#Ответ) с заполненными код/заголовки/тело.

Статус-строка ответа несёт настоящую фразу-причину для кода (`200 OK`,
`404 Not Found`, `500 Internal Server Error` и т. п. - курируемый список
самых частых кодов, иначе - обобщённая фраза по классу первой цифры
`1xx`-`5xx`, например `499` даёт `Client Error`) - значения не имеет для
обработки (клиенты ориентируются на числовой код), но не "OK" безусловно.

!!! note "HTTP keep-alive и `Connection`/`Content-Length` по умолчанию"
    Ответ несёт `Connection: keep-alive`/`Content-Length: <длина тела>`
    ТОЛЬКО ЕСЛИ программа не задала заголовок с тем же именем сама в
    `ответ.заголовки` - собственный заголовок побеждает, дубликата не
    возникает. Решение - читать ли следующий запрос на этом же соединении
    (вызвать `принять_http` ещё раз) или закрыть сокет - остаётся за
    вызывающим Rech-кодом, не рантаймом: см. `значение_заголовка` ниже и
    пример цикла в `examples/проекты/http_сервер/исходники/сервер.rech`
    (`обработать_соединение`). Чтобы РЕАЛЬНО известить клиента о закрытии -
    задайте `Connection: close` самостоятельно в `ответ.заголовки`.

#### `значение_заголовка`

```
значение_заголовка(заголовки: Строка, имя: Строка): ?Строка
```

Общий разбор HTTP-заголовков - не привязан к `Запрос`/`Ответ`, обе сущности
несут поле `заголовки` тем же форматом строки. Первое совпадение по
порядку появления - для повторяющихся заголовков смотрите
`значения_заголовка` ниже.

- `заголовки` - строка заголовков (`запрос.заголовки` или
  `ответ.заголовки`).
- `имя` - имя заголовка. Совпадение БЕЗ УЧЁТА РЕГИСТРА (RFC 7230 §3.2 -
  имя поля заголовка регистронезависимо) - в отличие от `значение_куки`
  ниже, где регистр ИМЕНИ cookie значим по RFC 6265.

`Ничто` - заголовок с таким именем не найден. Типичное применение - решить,
хочет ли клиент закрыть keep-alive соединение:
`(значение_заголовка(запрос.заголовки, "Connection") ?? "") == "close"`.

#### `значения_заголовка`

```
значения_заголовка(заголовки: Строка, имя: Строка): Список<Строка>
```

Как `значение_заголовка` выше, но отдаёт ВСЕ совпадения по порядку
появления, не только первое - настоящие HTTP-заголовки МОГУТ повторяться
(`X-Forwarded-For` от цепочки прокси, несколько `Accept` и т. п.). Пустой
список, не `Ничто`/паника - если имя не встретилось ни разу.

#### `параметры_пути`

```
параметры_пути(путь: Строка): Словарь<Строка, Строка>
```

- `путь` - путь запроса вместе с query-строкой (например,
  `"/поиск?a=1&b=два"`).

Разбирает часть после `?` в словарь "имя параметра -> значение".

#### `значение_куки`

```
значение_куки(запрос: Запрос, имя: Строка): ?Строка
```

- `запрос` - входящий `Запрос` (читает заголовок `Cookie`).
- `имя` - имя искомой cookie.

`Ничто` - cookie с таким именем не найдена.

#### `строка_куки`

```
строка_куки(имя: Строка, значение: Строка, опции: ОпцииКуки): Строка
```

Строит строку для заголовка ответа `Set-Cookie`.

- `имя` - имя cookie.
- `значение` - значение cookie.
- `опции` - сущность [`ОпцииКуки`](#ОпцииКуки) (путь/домен/срок жизни/
  флаги безопасности).

#### `принять_http_байты`/`отправить_http_ответ_байты`

```
принять_http_байты(сокет: Сокет): ЗапросБайты
отправить_http_ответ_байты(сокет: Сокет, ответ: ОтветБайты)
```

Те же операции, что `принять_http`/`отправить_http_ответ` выше, но `тело:
Список<Байт>`, не `тело: Строка` - бинарно-безопасно (`Строка` - только
текст, невалидные байты становятся `�`).
`ЗапросБайты`/`ОтветБайты` - отдельные сущности с теми же остальными
полями (метод/адрес/порт/путь/заголовки - обычная `Строка`), не поле в
`Запрос`/`Ответ` (иначе КАЖДАЯ программа платила бы за машинерию
`Список<Байт>` просто из факта существования этих функций в языке).

#### `разобрать_multipart`

```
разобрать_multipart(тело: Список<Байт>, заголовки: Строка): Список<ЧастьФормы>
```

Разбирает `multipart/form-data` (RFC 2046/7578) - настоящую HTML-форму с
`<input type=file>` (или `curl -F`) - на части.

- `тело` - бинарно-безопасное тело запроса (`ЗапросБайты.тело`, см.
  `принять_http_байты` выше - `multipart/form-data` требует бинарной
  безопасности, обычный `принять_http` не подойдёт).
- `заголовки` - заголовки того же запроса (`ЗапросБайты.заголовки`) - нужны
  ради границы (`boundary`) из `Content-Type`.

`ЧастьФормы` - сущность: `имя` (значение `name=` из `Content-Disposition`),
`имя_файла` (значение `filename=`, пустая `Строка` - обычное текстовое
поле формы, не файл), `тип_содержимого` (`Content-Type` ЭТОЙ части,
пустая `Строка` - не указан), `данные` (тело части, `Список<Байт>`).
Курируемый минимум, не полный RFC-парсер - без вложенных multipart и
`Content-Transfer-Encoding`; несколько частей одного `name` - все по
порядку в списке результата, вызывающий код сам решает, что с ними делать.

### БД

#### `подключиться_к_бд`

```
подключиться_к_бд(строка_подключения: Строка): БД
```

- `строка_подключения` - `"sqlite:путь"` (или `"sqlite::memory:"`),
  `"postgres://пользователь:пароль@хост:порт/база"`, или
  `"mysql://пользователь:пароль@хост:порт/база"`. Схема (префикс до `:`)
  решает, какая СУБД используется.

Открывает ПУЛ соединений (по умолчанию 4, настраивается через
`.rechproj`, `бд.размер_пула`) - см. примечание ниже. Ожидание свободного
соединения из пула можно ограничить (`.rechproj`, `бд.таймаут_пула_мс`, по
умолчанию 0 - ждать бесконечно) - при превышении `запросить`/`выполнить`
бросают `ОшибкаБД` вместо бесконечного ожидания. Для
SQLite - отдельная настройка `бд.sqlite_таймаут_блокировки_мс` (по
умолчанию 5000): сколько сама SQLite ждёт снятия блокировки файла ДРУГИМ
соединением/процессом - другое понятие, не таймаут пула этого рантайма
выше.

**Паникует**, если: строка подключения не начинается ни с `"sqlite:"`, ни
с `"postgres://"`/`"postgresql://"`, ни с `"mysql://"` ("подключиться_к_бд:
неизвестная схема строки подключения..."); или сама СУБД отклонила
подключение - неверные учётные данные, недоступный сервер и т. п.
("подключиться_к_бд: не удалось подключиться" - причина дальше не
различается, текст строки подключения в сообщение не попадает, она может
нести пароль).

#### `запросить`

```
запросить(бд: БД, sql: Строка, параметры: Список<Значение> = новый Список<Значение>()): Список<Словарь<Строка, Значение>>
```

- `бд` - открытое соединение (результат `подключиться_к_бд`).
- `sql` - текст SQL-запроса; `?` - единый плейсхолдер параметров во всех
  трёх СУБД (не нативное параметризованное связывание каждой библиотеки).
- `параметры` - **необязательный** (по умолчанию - пустой список, если у
  запроса нет `?`) список значений по порядку следования `?` в `sql`,
  каждое заранее боксировано в `Значение` (`(Значение) x`).

Каждая строка результата - `Словарь<Строка, Значение>` ("имя колонки" ->
значение), схема заранее не описывается.

**Паникует**, если: СУБД вернула ошибку выполнения (некорректный SQL,
отсутствующая таблица и т. п. - "запросить: ошибка выполнения запроса
\"<sql>\""); в `sql` больше `?`, чем элементов в `параметры`
("недостаточно параметров БД..."); элемент `параметры` боксирует значение
типа, для которого нет представления в SQL - допустимы только
`Целое`/`Действительное`/`Строка`/`Логическое`/`Ничто` ("недопустимый тип
параметра БД..."); свободное соединение не освободилось за
`бд.таймаут_пула_мс` (см. выше, "БД: не удалось получить свободное
соединение из пула вовремя").

#### `выполнить`

```
выполнить(бд: БД, sql: Строка, параметры: Список<Значение> = новый Список<Значение>()): Целое
```

То же самое для запросов без таблицы результата (`INSERT`/`UPDATE`/
`DELETE`/DDL).

- `бд`, `sql`, `параметры` - см. `запросить` выше (`параметры` так же
  необязателен).

Возвращает число затронутых строк.

**Паникует** - те же условия, что у `запросить` выше (текст сообщения об
ошибке самого запроса - "выполнить: ошибка выполнения запроса \"<sql>\"",
остальные три сообщения - буквально те же).

#### `закрыть_бд`

```
закрыть_бд(бд: БД)
```

- `бд` - соединение, закрываемое целиком (весь пул).

!!! note "Пул соединений"
    Одно значение `БД` - это пул из нескольких живых соединений, не одно.
    Запросы из разных потоков (`запустить`) обслуживаются параллельно, не
    выстраиваясь в очередь на одно общее соединение. SQLite `:memory:` -
    исключение: пул всегда 1 (иначе каждое соединение видело бы свою,
    независимую от остальных, базу, и запись через одно было бы не видно
    через другое).

#### `состояние_пула`

```
бд.состояние_пула(): СостояниеБД
```

Живой снимок пула соединений (см. примечание выше) - только МЕТОД, у этой
функции нет свободной формы (получать состояние снаружи можно, устанавливать
его - нет, сеттера не существует вовсе). `СостояниеБД` *(затеняемая, docs/
SPEC.md, раздел 6, "Затенение встроенных сущностей")* - три поля `Целое`:

- `всего` - настроенный размер пула (`бд.размер_пула`, по умолчанию 4).
- `занято` - сколько соединений сейчас выданы `запросить`/`выполнить`.
- `простаивает` - свободные прямо сейчас (`всего == занято + простаивает`
  всегда).

```
переменная сост = бд.состояние_пула()
вывести сост.занято
```

#### Метод-стиль

`бд.запросить(...)`/`бд.выполнить(...)`/`бд.закрыть()`/`бд.состояние_пула()` -
то же самое, что одноимённые свободные функции выше (`запросить(бд, ...)`
и т. д.), получатель становится первым аргументом - оба стиля
взаимозаменяемы. `подключиться_к_бд` остаётся только свободной функцией.

#### `начать_транзакцию`

```
начать_транзакцию(бд: БД, обработчик: Вызываемый(Транзакция): Ничто)
```

- `бд` - открытое соединение (результат `подключиться_к_бд`).
- `обработчик` - колбэк, получающий закреплённое на всё время транзакции
  соединение как [`Транзакция`](#Транзакция); штатное завершение колбэка
  фиксирует транзакцию (`COMMIT`), исключение/паника внутри него или явный
  `откатить()` - откатывает (`ROLLBACK`). Вложенная транзакция -
  `тр.вложенная(...)` (см. [`Транзакция`](#Транзакция)).

Только свободная форма, метод-стиля нет (в отличие от `запросить`/
`выполнить`/`закрыть` выше).

```
начать_транзакцию(бд, функция(тр: Транзакция)
{
    тр.выполнить("UPDATE счета SET баланс = баланс - ? WHERE ид = ?", [100, 1])
    тр.выполнить("UPDATE счета SET баланс = баланс + ? WHERE ид = ?", [100, 2])
})
```

### Время

```
время(): Целое
время_как_дата(метка: Целое): ДатаВремя
дата_как_время(дата: ДатаВремя): Целое
дату_в_строку(дата: ДатаВремя): Строка
разобрать_дату(строка: Строка): ?ДатаВремя
время_как_дата_в_поясе(метка: Целое, пояс: Строка): ?ДатаВремя
дата_в_поясе_как_время(дата: ДатаВремя, пояс: Строка): ?Целое
день_недели(дата: ДатаВремя): Целое
дату_в_читаемом_виде(дата: ДатаВремя): Строка
```

`время` - без параметров, текущий момент как unix-метка (секунды с
1970-01-01 UTC).

- `метка` - (у `время_как_дата`/`время_как_дата_в_поясе`) unix-метка для
  распаковки в календарные поля.
- `дата` - (у `дата_как_время`/`дату_в_строку`/`дата_в_поясе_как_время`/
  `день_недели`/`дату_в_читаемом_виде`) сущность [`ДатаВремя`](#ДатаВремя).
  `дата_как_время` - обратное к `время_как_дата`; `дату_в_строку`
  форматирует как `"ГГГГ-ММ-ДД ЧЧ:ММ:СС"`.
- `разобрать_дату` - обратное к `дату_в_строку`, `Ничто` при неверном
  формате.
- `пояс` - имя часового пояса базы IANA tzdata (`"Europe/Moscow"`,
  `"America/New_York"`, ...) - `время_как_дата_в_поясе` раскладывает
  метку в МЕСТНОЕ время указанного пояса (с учётом перехода на летнее
  время по реальной исторической базе), `дата_в_поясе_как_время` -
  обратное; обе `Ничто` при нераспознанном имени пояса. База встроена в
  собранную программу (не зависит от ОС и установки `rech`), переменная
  окружения `TZDIR` подменяет её без пересборки.
- `день_недели` - 0 (воскресенье) .. 6 (суббота).
- `дату_в_читаемом_виде` - относительное время в стиле Carbon'овского
  `diffForHumans()` ("5 минут назад"/"через 2 часа"), сравнивает с
  ТЕКУЩИМ моментом.

`ДатаВремя` несёт также методы того же назначения (синтаксический сахар
поверх функций выше - `д.добавить_дни(5)`, `д.в_поясе("Europe/Moscow")`,
`д.раньше(другая)`/`д.позже(другая)`, `д.разница_в_днях(другая)`/
`разница_в_часах`/`разница_в_секундах`, `д.является_выходным()`,
`д.в_читаемом_виде()`; `вычесть_дни`/`вычесть_часы`/`вычесть_минуты`/
`вычесть_секунды` - симметрично `добавить_*`).

### Крипто

```
хеш(алгоритм: АлгоритмХеша, данные: Строка): Строка
подпись_hmac_sha256(данные: Строка, ключ: Строка): Строка
закодировать_base64url(строка: Строка): Строка
декодировать_base64url(строка: Строка): Строка
```

- `алгоритм` - член встроенного перечисления `АлгоритмХеша`: `SHA256`,
  `SHA1`, `MD5`, `SHA512`, `SHA3_256`.
- `данные` - строка, которую нужно хешировать/подписать.
- `ключ` - (у `подпись_hmac_sha256`) секретный ключ подписи - та же
  основа, что у подписи JWT HS256.
- `строка` - (у кодирования/декодирования base64url) исходная/закодированная
  строка.

`хеш`/`подпись_hmac_sha256` возвращают HEX-строку (64/40/32/128/64 символов
для SHA256/SHA1/MD5/SHA512/SHA3_256 соответственно). `SHA1`/`MD5`
криптографически сломаны (известны коллизии) - не для новых
паролей/подписей (для этого - `SHA256`/`SHA512`/`SHA3_256`), только для
совместимости с внешними форматами (SHA-1 - объекты Git; MD5 - контрольные
суммы/ETag). `SHA3_256` - принципиально другая конструкция (Keccak-sponge),
чем у остальных - НЕ замена `SHA256`/`SHA512`. Значение `алгоритм` вне
членов перечисления (голое Целое напрямую, не через сам enum) - аварийное
завершение.

Примеры:
```
хеш(АлгоритмХеша.SHA256, "пароль")
хеш(АлгоритмХеша.SHA1, "текст")
```

`закодировать_base64url`/`декодировать_base64url` - RFC 4648 §5, без
`=`-паддинга.

```
зашифровать(данные: Строка, ключ: Строка): Строка
расшифровать(шифротекст: Строка, ключ: Строка): Строка
```

- `данные` - открытый текст. `ключ` - строка ЛЮБОЙ длины (внутри - её
  SHA-256 как настоящий 256-битный ключ AES). `шифротекст` - результат
  `зашифровать`.

AES-256-GCM (аутентифицированное шифрование). Возврат `зашифровать` -
самодостаточная HEX-строка (nonce + шифротекст + тег аутентификации) -
передать целиком в `расшифровать`, без отдельных параметров. Шифротекст
непредсказуем (свежий случайный nonce на каждый вызов) - сравнивать можно
только round trip, не конкретное значение. `расшифровать` бросает
`ОшибкаКриптографии` на неверном ключе или изменённом шифротексте и
`ОшибкаРазбора` на некорректном входе (не-HEX,
короче минимума).

Пример:
```
переменная шифротекст = зашифровать("секрет", "пароль")
расшифровать(шифротекст, "пароль")  // "секрет"
```

```
сгенерировать_приватный_ключ(алгоритм: АлгоритмПодписи): Строка
получить_публичный_ключ(приватный_ключ: Строка): Строка
подписать(данные: Строка, приватный_ключ: Строка): Строка
проверить_подпись(данные: Строка, подпись: Строка, публичный_ключ: Строка): Логическое
```

- `алгоритм` - член перечисления `АлгоритмПодписи`: `RSA` (2048 бит),
  `Ed25519`.
- Ключи - PEM-текст, совместимый с настоящим `openssl` (`openssl pkey`/
  `openssl dgst -sign`/`openssl pkeyutl` и т. п.), не только с самим
  Rech. `получить_публичный_ключ` выводит публичный ключ из приватного -
  отдельной "пары ключей" как значения нет.
- `подписать` возвращает подпись в виде HEX-строки. `проверить_подпись`
  возвращает `Логическое` - `ложь` на несовпавшей подписи (неверный ключ
  или изменённые данные), `ОшибкаРазбора` только на структурно некорректном
  входе (подпись не в HEX, ключ не в PEM).

Пример:
```
переменная приватный_ключ = сгенерировать_приватный_ключ(АлгоритмПодписи.Ed25519)
переменная публичный_ключ = получить_публичный_ключ(приватный_ключ)
переменная подпись = подписать("сообщение", приватный_ключ)
проверить_подпись("сообщение", подпись, публичный_ключ)  // истина
```

### Изображения

```
декодировать_изображение(путь: Строка, формат: ФорматИзображения): ДекодированноеИзображение
закодировать_изображение(путь: Строка, ширина: Целое, высота: Целое, пиксели: Список<Байт>, формат: ФорматИзображения, качество: Целое)
```

- `формат` - член встроенного перечисления `ФорматИзображения`: `PNG`,
  `JPEG`.
- `ДекодированноеИзображение` - встроенная структура *(затеняемая, docs/
  SPEC.md, раздел 6, "Затенение встроенных сущностей")*: `ширина`/`высота:
  Целое`, `пиксели: Список<Байт>` - построчно, 4 байта на пиксель (RGBA).
- `пиксели` - (у `закодировать_изображение`) тот же формат (RGBA
  построчно). `качество` - 0-100, используется только форматом `JPEG` (у
  `PNG` сжатие без потерь, параметр игнорируется).
- PNG хранит альфа-канал как есть; JPEG её не поддерживает физически -
  кодирование в JPEG отбрасывает альфу, декодирование восстанавливает её
  как 255 (непрозрачный).
- Значение `формат` вне членов перечисления (голое Целое напрямую, не
  через сам enum) - аварийное завершение.

Пример:
```
переменная декод = декодировать_изображение("фото.png", ФорматИзображения.PNG)
вывести декод.ширина
закодировать_изображение("копия.jpg", декод.ширина, декод.высота, декод.пиксели, ФорматИзображения.JPEG, 90)
```

Пиксельный буфер + BMP (свой формат, без внешней библиотеки) и примитивы
рисования поверх него - `examples/изображения/растровое_изображение.rech`/
`примитивы.rech`. Удобная обёртка над `декодировать_изображение`/
`закодировать_изображение`, работающая с той же пользовательской
сущностью `Изображение` (не с `ДекодированноеИзображение`) -
`examples/изображения/png_jpeg.rech`: `загрузить_png`/`сохранить_png`/
`загрузить_jpeg`/`сохранить_jpeg`, а также `загрузить_изображение(путь):
Изображение` - определяет формат (BMP/PNG/JPEG) по сигнатуре первых байт
файла, не по расширению имени.

### Переменные окружения

```
получить_переменную_окружения(имя: Строка): ?Строка
```

- `имя` - имя переменной окружения.

`Ничто`, если такая переменная не установлена (не пустая строка - пустое

### Опции проекта

```
опции_проекта(): Строка
установить_опции_проекта(текст: Строка): Пусто
```

`опции_проекта()` - сырой YAML-текст секции `опции:` файла проекта
(`.rechproj`) как есть, `""` без секции/файла проекта - не `Ничто`, не
ошибка. В отличие от остального `.rechproj` (ограниченный формат), `опции:`
- настоящий YAML произвольной вложенности - обычно читается сразу через
`разобрать YAML опции_проекта() как <Тип>` (docs/SPEC.md, раздел 18):

```
переменная конфигурация = разобрать YAML опции_проекта() как МойТип
```

`установить_опции_проекта(текст)` - `текст` заменяет то, что вернёт
следующий `опции_проекта()`, но ТОЛЬКО в памяти ТЕКУЩЕГО запуска процесса
(`.rechproj` на диске не меняется - PHP `ini_set`-стиль); после
перезапуска снова используется встроенное при сборке значение. Типичный
парный вызов - изменить разобранное значение и записать его назад целиком:

```
конфигурация.поле = новое_значение
установить_опции_проекта(сериализовать YAML конфигурация)
```

Пример - `examples/проекты/опции_проекта/`.

## Типы и сущности

### Примитивы

| Тип | Описание |
|---|---|
| `Строка` | Строка UTF-8. Null-terminated C-строка без отдельно хранимой длины (см. предупреждение выше) |
| `Целое` | 64-битное знаковое целое число. Литерал - десятичный (`42`) либо с явным префиксом системы счисления: `0x`/`0X` (шестнадцатеричный), `0o`/`0O` (восьмеричный), `0b`/`0B` (двоичный) |
| `Целое64` | Синоним `Целое` (`синоним Целое = Целое64`) - один и тот же тип, смешиваются без приведения |
| `Целое8` / `Целое16` / `Целое32` | Знаковые целые фиксированной ширины - арифметика/сравнение строго между операндами одного типа, без неявного приведения |
| `Натуральное` / `Натуральное16/32` | Целые без знака, та же логика ширины; `Натуральное` - 64 бита |
| `Натуральное64` | Синоним `Натуральное` (`синоним Натуральное = Натуральное64`) - один и тот же тип |
| `Действительное` | Число с плавающей точкой двойной точности (C `double`) |
| `Дробное` | Число с плавающей точкой одинарной точности (C `float`) |
| `Символ` | Одна кодовая точка Unicode (не байт) |
| `Байт` | 8 бит без знака, `[0, 255]`, арифметика по модулю 256; `Натуральное8` - его синоним (`синоним Байт = Натуральное8`) |
| `Логическое` | `истина` / `ложь` |
| `Файл` | Непрозрачный дескриптор открытого файла |
| `Сокет` | Непрозрачный дескриптор сетевого сокета |
| `БД` | Непрозрачный дескриптор соединения с БД - на деле пул из нескольких соединений |
| `Задача` / `Задача<Вызываемый(...): Тип>` | Дескриптор задачи, запущенной `запустить`/`поручить` - используется с `дождаться`. В `<...>` - сигнатура запущенного (тип `Вызываемый` или его синоним): задачи одной сигнатуры - один тип, будь то функция, лямбда, метод, поток или корутина (`Список<Задача<Вызываемый(Целое): Целое>>`). Голая `Задача` (без `<...>`) - менее конкретная, принимает задачу ЛЮБОЙ сигнатуры, но саму `дождаться` на ней написать нельзя |

### Generic-коллекции

#### `Список<T>`

```
добавить(значение: T)
получить(индекс: Целое): T
установить(индекс: Целое, значение: T)
удалить(индекс: Целое): T
первый(): T
последний(): T
длина(): Целое
пусто(): Логическое
равен(другой: Список<T>): Логическое
```

Растущий список.

- `значение` - (у `добавить`/`установить`) элемент типа `T`.
- `индекс` - (у `получить`/`установить`/`удалить`) позиция элемента, с 0.
  Выход за границу - аварийное завершение.
- `удалить` сдвигает элементы после `индекс` на одну позицию влево и
  возвращает удалённый элемент.
- `первый`/`последний` - равносильны `получить(0)`/
  `получить(длина() - 1)`, аварийно завершаются на пустом списке.
- `равен` - сравнивает СОДЕРЖИМОЕ (та же длина, равные элементы по
  порядку) - в отличие от `==`, которое (как и у любой сущности) сравнивает
  по identity. Есть, только когда `T` сам сравним (примитив/`Строка`/
  `структура`/сущность/другая встроенная коллекция).

Индексация также доступна как оператор: `список[i]` (чтение - `?T`,
`Ничто` вне границ; запись), `&список[i]` (взять адрес элемента - см.
`Указатель<T>`). Цепочка `таблица[i][j]` - тоже `?T`, `Ничто` протекает.

#### `Стопка<T>`

```
положить(значение: T)
снять(): T
верх(): T
длина(): Целое
пусто(): Логическое
значения(): Список<T>
```

Стек, LIFO.

- `значение` - (у `положить`) элемент, добавляемый на вершину.
- `снять` - без параметров, убирает и возвращает верхний элемент (паника
  на пустой стопке).
- `верх` - без параметров, возвращает верхний элемент, не убирая его.
- `значения` - новый список элементов сверху вниз (тот же порядок, что у
  `для x в стопке`).

#### `Очередь<T>`

```
добавить(значение: T)
извлечь(): T
первый(): T
длина(): Целое
пусто(): Логическое
значения(): Список<T>
```

Очередь, FIFO.

- `значение` - (у `добавить`) элемент, добавляемый в конец очереди.
- `извлечь` - без параметров, убирает и возвращает первый элемент.
- `первый` - без параметров, возвращает первый элемент, не убирая его.
- `значения` - новый список элементов от первого к последнему.

#### `Множество<T>`

```
добавить(элемент: T)
содержит(элемент: T): Логическое
удалить(элемент: T)
длина(): Целое
пусто(): Логическое
значения(): Список<T>
равен(другой: Множество<T>): Логическое
```

Набор без повторов: `добавить` уже имеющегося элемента ничего не меняет,
`для x в множестве` и `значения()` - в порядке добавления, `равен` - те же
элементы без учёта порядка. Тип элемента - как ключ `Словарь`
(`Целое`/`Байт`/`Символ`/`Логическое`/`Строка`, перечисление).

#### `Словарь<К, В>`

```
установить(ключ: К, значение: В)
получить(ключ: К): В
содержит(ключ: К): Логическое
удалить(ключ: К)
длина(): Целое
пусто(): Логическое
ключи(): Список<К>
значения(): Список<В>
равен(другой: Словарь<К, В>): Логическое
```

Хеш-словарь с порядком вставки ключей.

- `ключ` - ключ типа `К` (только `Целое`/`Байт`/`Символ`/`Логическое`/
  `Строка` - не `Действительное`/`Дробное`, равенство чисел с плавающей
  точкой ненадёжно).
- `значение` - (у `установить`) значение типа `В`, сопоставляемое ключу.
- `ключи`/`значения` - новые списки ключей/значений в порядке вставки
  (тот же порядок, что у `для ключ, значение в словаре`; перезапись
  значения место ключа не меняет).
- `равен` - сравнивает содержимое (тот же принцип, что и `Список<T>.равен`
  выше), без учёта порядка вставки. Есть, только когда `В` само сравнимо.

`получить` на отсутствующем ключе - аварийное завершение (сперва
проверяйте `содержит`).

#### `Тип[N]` - массив фиксированной длины

```
м[i]                          // элемент; вне границ - ВыходЗаГраницы
м[i] = значение
получить(индекс: Целое): T
установить(индекс: Целое, значение: T)
длина(): Целое                // N
```

Значение (копируется при присваивании и передаче), без начального
значения - нули. `N` - число или целая константа модуля (`Байт[ДЛИНА]`). `Тип[N][M]` - двумерный, `*Тип[N]` - массив указателей.
Годится полем `внешняя структура` (C `тип имя[N]`).

#### `Указатель<T>`

Адрес значения `T` (переменная/параметр, поле сущности, элемент списка).
`&получатель` берёт адрес, `*значение` разыменовывает. Каждая форма - не
более одного уровня.

Указатель индексируется как C-массив, без проверки границ:

```
п[i]                  // i-й элемент, тип T
п[i] = значение       // запись i-го элемента
&п[i]                 // адрес i-го элемента: Указатель<T>
получить(индекс: Целое): T
установить(индекс: Целое, значение: T)
```

Приведение - между указателями, числом-адресом (`Целое`/`Натуральное`) и
внешней сущностью:

```
(*Целое32) сырая      // другой тип элемента
(Указатель<Байт>) п   // то же, полная запись
(Целое) п             // адрес числом
(*Байт) адрес         // число - снова указатель
```

### Рефлексия

#### `Тип`

Дескриптор типа - результат `тип Имя`. Два `Тип` сравниваются `==`/`!=`
(один и тот же тип; встроенные синонимы равны - `тип Натуральное8 == тип
Байт`).

```
имя(): Строка
число_полей(): Целое
имя_поля(индекс: Целое): Строка
тип_поля(индекс: Целое): Тип
тег_поля(индекс: Целое, ключ: Строка): Строка
тег_поля_текст(индекс: Целое): Строка
индекс_поля_по_тегу(ключ: Строка, значение: Строка): ?Целое
число_методов(): Целое
имя_метода(индекс: Целое): Строка
число_параметров_метода(индекс: Целое): Целое
тип_параметра_метода(индекс: Целое, параметр: Целое): Тип
тип_результата_метода(индекс: Целое): Тип
тег_метода(индекс: Целое, ключ: Строка): Строка
тег_метода_текст(индекс: Целое): Строка
создать(аргументы: Список<Значение>): Значение
тег(ключ: Строка): Строка
тег_текст(): Строка
базовый_тип(): Тип
наследует_ли(тип: Тип): Логическое
число_интерфейсов(): Целое
получить_интерфейс(индекс: Целое): Тип
реализует_ли(тип: Тип): Логическое
```

- `индекс` - позиция поля/метода, с 0 (по `число_полей`/`число_методов`).
- `параметр` - (у `тип_параметра_метода`) позиция параметра МЕТОДА, с 0
  (по `число_параметров_метода`).
- `ключ` - имя ключа тега (например, `"json"`/`"sql"` у
  `` `json:name, sql:user_name` ``); `""` - тега или ключа в нём нет.
- `аргументы` - (у `создать`) позиционные аргументы конструктора,
  каждый заранее боксирован в `Значение`.
- `тип` - (у `наследует_ли`/`реализует_ли`) сравниваемый тип/интерфейс.

`индекс_поля_по_тегу` - обратное направление к `тег_поля`: дан не индекс
поля, а пара (ключ, значение) тега, `Ничто` - тег с таким ключом и
значением не найден ни у одного поля.

#### `Значение`

Боксированное значение любого типа - результат `(Значение) x`.

```
тип_значения(): Тип
получить_поле(имя: Строка): Значение
получить_поле_по_тегу(ключ: Строка, значение: Строка): ?Значение
установить_поле(имя: Строка, значение: Значение)
вызвать(имя: Строка, аргументы: Список<Значение>): Значение
```

- `имя` - имя поля/метода (у `получить_поле`/`установить_поле`/`вызвать`).
- `значение` - (у `установить_поле`) новое боксированное значение поля.
- `аргументы` - (у `вызвать`) позиционные аргументы метода, каждый
  боксирован в `Значение`.

`получить_поле_по_тегу` - обратное направление к `получить_поле`, тем же
принципом, что `Тип.индекс_поля_по_тегу` выше: дана пара (ключ, значение)
тега, не имя поля, `Ничто` - не найдено.

Разбоксируется явным `x как Тип` (аварийное завершение при несовпадении
фактического типа с `Тип`).

### Встроенные сущности

Пометка "затеняемая" у сущности ниже означает - её можно объявить заново
своей версией (docs/SPEC.md, раздел 6, "Затенение встроенных сущностей");
действует в файле, который её объявил, или явно `использовать <Имя> из
"..."` на неё - остальные файлы программы продолжают видеть builtin-версию
без изменений.

<a id="Блокировка"></a>
**`Блокировка`** (мьютекс - синхронизация между потоками): методы
`захватить()`/`освободить()`, без параметров.

<a id="Семафор"></a>
**`Семафор`** (счётный мьютекс - обобщение `Блокировки` на N разрешений
вместо одного): `новый Семафор(начальное_значение: Целое)`, методы
`захватить(таймаут_мс: Целое = -1)`/`освободить()`. `таймаут_мс` у
`захватить`: `-1` (по умолчанию) - ждать освобождения бесконечно, `0` - не
ждать вовсе (немедленная паника, если свободных разрешений нет), `N > 0` -
ждать не дольше N миллисекунд, прежде чем так же паниковать.

<a id="Транзакция"></a>
**`Транзакция`** (закреплённое на время транзакции соединение с БД -
параметр колбэка [`начать_транзакцию`](#начать_транзакцию), нет `новый`):
методы `запросить(...)`/`выполнить(...)` - те же самые, что у `БД`, но на
этом закреплённом соединении, `откатить()` - немедленный откат и
`вложенная(обработчик: Вызываемый(Транзакция): Ничто)` - вложенная
транзакция (`SAVEPOINT`) на том же соединении: штатный возврат колбэка
фиксирует её (`RELEASE SAVEPOINT`), исключение/паника/`откатить()` -
откатывает только сделанное внутри неё (`ROLLBACK TO SAVEPOINT`), внешняя
транзакция продолжается; использование `Транзакция` после `откатить()` или
после возврата из колбэка - ошибка (транзакция уже закрыта).

<a id="Исключение"></a>
**`Исключение`** - базовый тип для пользовательского исключения
(`сущность X наследует Исключение`), поле `сообщение: Строка`.

Встроенные исключения - наследники `Исключение`, их бросают сами встроенные
функции; ловятся по имени или как `Исключение`:

<a id="ОшибкаФайла"></a>
<a id="ОшибкаСети"></a>
<a id="ОшибкаБД"></a>
<a id="ОшибкаРазбора"></a>
<a id="ОшибкаПроцесса"></a>
<a id="ОшибкаКриптографии"></a>

| Исключение | Когда |
|---|---|
| **`ОшибкаФайла`** | файл не открылся/не прочитался/не записался, конец стандартного ввода, не определён `текущий_каталог()` |
| **`ОшибкаСети`** | сокет, TLS, HTTP, HTTP/2, gRPC: не подключились, не приняли соединение, обрыв при отправке/получении, нарушение протокола |
| **`ОшибкаБД`** | не удалось подключиться, запрос/команда не выполнились, нет свободного соединения в пуле вовремя |
| **`ОшибкаРазбора`** | `разобрать JSON`/`XML`/`YAML`/`PROTOBUF`, каст строки в число/`Символ`/`Логическое`, `прочитать_целое`/`прочитать_число`, hex/base64/PEM, `rgbцвет_из_hex`, multipart, PNG/JPEG |

### Встроенные интерфейсы

<a id="Строчный"></a>
**`Строчный`** (аналог `fmt.Stringer`/`toString()`) - единственный
встроенный интерфейс языка, объявлять его самому не нужно (и нельзя - `интерфейс
Строчный` в исходнике - ошибка компиляции). Один метод, `в_строку(): Строка`.
Сущность, `реализует Строчный`, печатается `вывести значение` результатом
`в_строку()`, а не плейсхолдером `[сущность]<Имя>`; `(Строка) значение` и
`${значение}` в шаблоне тоже дают `в_строку()`.

**`КодКлавиши`** (см. [`прочитать_код_клавиши`](#прочитать_код_клавиши)):
`A`..`Z`, `Цифра0`..`Цифра9`, `Вверх`, `Вниз`, `Влево`, `Вправо`, `Пробел`,
`Ввод`, `Escape`, `Tab`, `Backspace` - физический код клавиши, НЕ
зависящий от раскладки. Буквы/цифры - латиницей по ПОЗИЦИИ клавиши (как в
WASD-раскладке игр, не по напечатанному символу); остальные - как
физически подписана клавиша (то же имя даже на клавиатуре с русской
раскладкой). Числовые значения членов - внутренний индекс компилятора, тот
же принцип, что и у `СигналОС` выше.

## Ключевые слова и синтаксис

| Слово | Описание |
|---|---|
| `функция` | `функция имя(параметр: Тип, ...): ТипРезультата { ... }` - можно объявить несколько функций (или простых методов сущности) с одним именем, но разным списком типов параметров (перегрузка, [SPEC.md, раздел 25](SPEC.md#25-перегрузка-функций-и-методов)) |
| `вывести` | `вывести <выражение>` - печатает значение, без переноса строки (для переноса добавьте `\n` в саму строку) |
| `показать` | `показать <выражение>` - отладочный вывод: значение вместе с именем типа |
| `переменная` | `переменная имя = выражение` - тип вычисляется из значения (с явным типом - `Тип имя = выражение`; без значения - `Тип имя`) |
| `и` / `или` / `не` | Логические И/ИЛИ (короткое замыкание, синонимы `&&`/`\|\|`) / отрицание (синоним `!`) |
| `истина` / `ложь` | Логические литералы |
| `если` / `иначе` | `если <условие> { ... } [иначе { ... }]` |
| `пока` | Цикл с предусловием: `пока <условие> { ... }` |
| `для` / `от` / `до` / `в` | `для имя от начало до конец { ... }`, `для имя в коллекция { ... }` или общий `для инициализация; условие; шаг { ... }` (`для Целое32 i = 0; i < n; i++`, `для Байт б от 0 до 255`, `для Строка к, Целое з в словаре` - тип переменной явно) (все три секции необязательны, как в C - `для ;; { ... }` бесконечен) |
| `прервать` / `прервать N` | Немедленный выход из N-го по счёту (считая текущий, 1 по умолчанию) охватывающего цикла |
| `продолжить` / `продолжить N` | Пропускает остаток текущей итерации N-го по счёту (считая текущий, 1 по умолчанию) охватывающего цикла и переходит к его следующей итерации |
| `вернуть` | `вернуть <выражение>` - возвращает значение из функции/метода |
| `сущность` / `класс` | `сущность Имя { имеет: ... }` - ссылочный тип (`класс` - синоним) |
| `структура` | `структура Имя { имеет: ... }` - тип ПО ЗНАЧЕНИЮ (копируется при присваивании/передаче) |
| `имеет` | Секция полей сущности/структуры: `[модификаторы] Тип имя [= значение]` - модификатор согласуется с типом (`приватная Строка имя`) |
| `новый` / `новая` / `новое` / `новые` | `новый Тип(...)` - словоформа согласуется по роду/числу с именем типа |
| `этот` | Ссылка на текущий объект внутри тела метода |
| `состояние` | Секция typestate-состояний: `состояние: имя1 имя2 ...` |
| `становится` | Переход состояния, согласованный по роду/числу и творительным падежом: `пользователь становится авторизованным` |
| `утверждать` | `утверждать <условие>[, <сообщение>]` - аварийно завершает программу, если условие ложно; необязательное `<сообщение>` (тип `Строка`) дописывается к стандартному тексту |
| `приватный` / `публичный` / `защищённый` | Модификаторы видимости поля/метода (все словоформы по роду/числу) |
| `внутренний` | Модификатор видимости ПЕРЕД `функция`/`сущность`/`класс`/`структура`/`перечисление`/`константа`/`синоним` верхнего уровня файла (не поля/метода) - видно любому файлу того же `.rechproj`-проекта, но не через `использовать ... из "имя_зависимости/путь"` (граница зависимости), [SPEC.md, раздел 10 "Импорты", "Модульная инкапсуляция"](SPEC.md#10-импорты) |
| `статический` | Общий на весь тип, не на экземпляр: `Тип::поле` / `Тип::метод(...)` |
| `абстрактный` | Перед `сущность`/`класс` - нельзя создать экземпляр напрямую |
| `использовать` / `из` / `как` | `использовать имя[, имя...] [как псевдоним] из "путь"` |
| `как` (каст) | Разбоксирование `значение как Тип` |
| `внешняя` | `внешняя функция ИмяC(...): Тип` (`...` последним без имени - вариативная C-функция), `внешняя Тип ИмяC` (C-переменная) - FFI |
| `константа` | `константа ИМЯ = значение` |
| `перечисление` | `перечисление Имя { Член1, Член2 = число, ... }` |
| `синоним` | `синоним Имя = Тип`, `синоним Имя<T> = Тип`, `синоним ?Имя = ?Тип` - другое имя того же типа, [SPEC.md, раздел 29](SPEC.md#29-синонимы-типов) |
| `интерфейс` | `интерфейс Имя { метод(...): Тип }` |
| `наследует` | `сущность Б наследует А { ... }` |
| `реализует` | `сущность Тип реализует Интерфейс { ... }` |
| `конструктор` | `конструктор(параметр: Тип, ...) { ... }` |
| `родитель` | Вызов конструктора базовой сущности - только первой инструкцией конструктора |
| `попытаться` / `поймать` | `попытаться { ... } поймать(имя: Тип1\|Тип2) { ... }` |
| `выбросить` | `выбросить <выражение>` - выбрасывает исключение |
| `относится` / `к` | `значение относится к Тип` |
| `запустить` | `запустить имя(...)` / `запустить объект.метод(...)` - запуск функции, значения `Вызываемый` или метода в отдельном потоке ОС, результат - `Задача<Вызываемый(...)>` |
| `дождаться` | `дождаться задача` - ожидание завершения |
| `асинхронная` | `асинхронная функция имя(...)` - `дождаться имя(...)` спавнит на планировщике корутин и сразу ждёт результат, `поручить имя(...)` - спавнит фоново, без ожидания; вызов без обоих - обычный синхронный вызов, [SPEC.md, раздел 15](SPEC.md#15-параллелизм) |
| `поручить` | `поручить имя(...)` - фоновый запуск `асинхронная функция`, результат - `Задача`, дожидается тем же `дождаться` |
| `экспортировать` | Видимость функции/сущности снаружи разделяемой библиотеки (`rech build --lib`) |
| `разобрать` / `сериализовать` | `разобрать JSON/XML/YAML/PROTOBUF <выражение> как <Тип>` / `сериализовать JSON/XML/YAML/PROTOBUF <выражение>` (PROTOBUF - `Список<Байт>`, не `Строка`; номер поля - обязательный тег `` `protobuf:N` ``) |
| `тип` | `тип Имя` - дескриптор типа (рефлексия) |
| `?Тип` / `Ничто` | Nullable-тип - допускает `Ничто` вдобавок к обычным значениям `Тип` |
| `выбрать` / `когда` | `выбрать <выражение> { когда <значение>[\|<значение>...]: ... иначе: ... }` |
| `оператор` | `статический [видимость] оператор <символ>(a: Тип, b: Тип): ТипРезультата { ... }` - перегрузка бинарного оператора (`+ - * / % == != < > <= >=`) для сущности/структуры, [SPEC.md, раздел 26](SPEC.md#26-перегрузка-операторов) |

### Операторы (по возрастанию приоритета)

| Оператор | Смысл |
|---|---|
| `? :` | Тернарный условный (выражение) - `условие ? тогда : иначе`; ветви строго одного типа. Elvis-форма `условие ?: иначе` (без `тогда`, как в PHP) - равносильна `условие или иначе` |
| `??` | null-coalescing - `a ?? b` даёт `a`, если не `Ничто`, иначе `b` |
| `или` / `\|\|` | Логическое ИЛИ |
| `и` / `&&` | Логическое И |
| `не` | Логическое отрицание (унарный); `!` - то же, но с приоритетом унарных (см. ниже) |
| `== != < > <= >=` | Сравнение - не цепочное; сущность/класс (не `структура`) и generic-коллекция - по ССЫЛКЕ (тот же ли объект), не по содержимому полей |
| `\|` | Побитовое ИЛИ, `Целое` или `Байт` (оба операнда одного из этих типов, результат того же типа) |
| `^` | Побитовое искл. ИЛИ, `Целое` или `Байт` |
| `&` | Побитовое И, `Целое` или `Байт` |
| `<< >>` | Сдвиги, `Целое` или `Байт` |
| `+ -` | Сложение/вычитание; `+` для `Строка` - конкатенация |
| `* /` | Умножение/деление - `/` между `Целое` на `0` аварийно завершает процесс |
| унарный `-`, `~`, `++ --`, `!` | Отрицание, побитовое НЕ (`Целое` или `Байт`), инкремент/декремент, `!x` - у `Логическое` отрицание (как `не x`), у nullable/`Указатель<T>` - синоним `x == Ничто` |

Скобки `( ... )` группируют явно и перекрывают любой приоритет.

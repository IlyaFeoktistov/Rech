# Грамматика Rech (проектный набросок)

Формальный набросок грамматики в духе EBNF. Не всё описанное здесь уже
реализовано - у каждого блока есть статус: `[v0.1]` - работает в текущем
компиляторе, `[шаг N]` - запланировано и привязано к конкретному шагу
[docs/ROADMAP.md](ROADMAP.md), без метки - архитектурное решение, которое
влияет на дизайн уже сейчас, но само по себе не отдельный шаг.

## Два представления одного AST

Ключевая идея: строгий и русский синтаксис - это два конкретных синтаксиса
(concrete syntax) для одного и того же AST, а не два разных языка.

```
строгий:   пользователь.войти("12345")
русский:   пользователь входит с паролем "12345"
```

Оба разбираются в один и тот же узел AST, например:

```
MethodCall{
    Receiver: пользователь
    Method:   войти
    Args:     ["12345"]
}
```

Отсюда архитектурное требование: front-end должен допускать несколько
конкретных синтаксисов (strict, natural), которые оба производят один и тот
же `internal/ast`, и должен существовать printer, печатающий AST обратно в
любое из представлений - это то, что нужно IDE для переключения между ними.
Это не отдельный шаг с датой готовности, а инвариант, который нужно соблюдать
при добавлении natural-синтаксиса начиная с шага 3.

## Программа

```
program     := { top_level }
top_level   := function | entity
```

## Функции

```
function    := "функция" IDENT [ "(" [ params ] ")" ] [ ":" type ] block
params      := param { "," param }
param       := IDENT ":" type
block       := "{" { statement } "}"
```

`[v0.1]`: без параметров, тело - только `вывести "строка"`.
`[шаг 1-3]`: параметры, возвращаемый тип, произвольные инструкции в теле.

## Сущности

```
entity      := ( "сущность" | "класс" ) IDENT "{" { member } "}"
member      := field | states_decl | method
field       := IDENT ":" type
states_decl := "состояние" ":" NEWLINE { IDENT NEWLINE }
method      := IDENT "(" [ params ] ")" [ ":" type ] block
```

`[шаг 4]`: `entity`, `field`, `method` без `states_decl`.
`[шаг 4.1]`: `states_decl`. `состояние: неавторизован авторизован` объявляет
конечный набор состояний объекта. Для каждого состояния `X` компилятор
синтезирует производный тип `<Прилагательное от X><Имя сущности>`, например
`АвторизованныйПользователь` (подробнее - раздел "Состояния и typestate").

## Инструкции

```
statement   := assign | if_stmt | while_stmt | print_stmt
             | become_stmt | call_stmt | gerund_stmt | return_stmt
assign      := IDENT "=" expr
if_stmt     := "если" condition block [ "иначе" block ]
while_stmt  := "пока" condition block
print_stmt  := "вывести" expr
return_stmt := "вернуть" [ expr ]
become_stmt := "этот" "становится" STATE_ADJ
```

`[v0.1]`: только `print_stmt`, и только со строковым литералом.
`[шаг 1]`: `assign`. `[шаг 2]`: `if_stmt`, `while_stmt`, `return_stmt`.
`[шаг 4.1]`: `become_stmt`.

`condition` и `call_stmt` могут быть как строгим вызовом (`X.метод(...)`),
так и естественной фразой (`X метод ...` с падежными аргументами) - см. ниже.

## Естественный вызов и падежное сопоставление `[шаг 3, движок - шаг 1.5]`

```
natural_call := ( IDENT | NOUN_PHRASE ) VERB_OR_IDENT { arg_phrase }
arg_phrase   := [ PREPOSITION ] NOUN_PHRASE
```

Движок из шага 1.5 (лемматизация + определение падежа словоформы) к моменту
реализации шага 3 уже существует, поэтому падежное сопоставление сразу
настоящее, а не шаблонное: параметры функции называются падежными
вопросительными словами - это одновременно имя параметра и его падежная
роль:

| имя параметра | падеж                  | пример словоформы при вызове |
|----------------|------------------------|-------------------------------|
| `кто`          | именительный           | пользователь                  |
| `кого`         | винительный (одуш.)    | пользователя                  |
| `кому`         | дательный              | пользователю                  |
| `кем`          | творительный           | (с) паролем                   |
| `где`          | предложный             | (в) системе                   |
| `что`          | винительный (неодуш.)  | сообщение                     |

Пример:

```
функция зарегистрировать(
    кого: ПользовательДанные,
    где: Система
): Пользователь
```

вызывается как:

```
зарегистрировать пользователя в системе
```

и разбирается так: словоформа `пользователя` определяется морфологией (шаг
1.5) как винительный падеж -> связывается с параметром `кого`; `в системе` ->
предложный падеж -> связывается с параметром `где`. Порядок слов в вызове
после этого не важен - роль определяется падежом, а не позицией в фразе.

## Деепричастная конструкция `[шаг 6.5]`

```
gerund_stmt := VERB_GERUND { arg_phrase } "," ( statement | block )
```

```
зарегистрировав пользователя "Илья" с паролем "секрет",
    войти в систему
```

разбирается как последовательность двух инструкций: вызов, соответствующий
деепричастию (`зарегистрировав` -> лемма `зарегистрировать`, совершенный вид
-> действие уже совершено к моменту главного), затем главная инструкция.

## Состояния и typestate `[шаг 4.1]`

```
STATE_ADJ   := IDENT   // согласованное по роду/падежу прилагательное состояния
```

`пользователь становится авторизованным` - изменение состояния объекта,
известное компилятору, а не присваивание обычного поля.

Производный тип `АвторизованныйПользователь` можно использовать в сигнатуре
параметра:

```
функция показатьПрофиль(пользователь: АвторизованныйПользователь)
```

Компилятор должен доказать при вызове, что на всех путях выполнения объект
уже прошёл переход в состояние `авторизован`, прежде чем разрешить передать
его в параметр этого типа - это flow-sensitive проверка на уровне IR (шаг 5),
а не просто проверка типов на уровне AST.

## Явные ограничения этого наброска

- Падежное сопоставление (шаг 3) не пытается разобрать произвольный русский
  текст - только фразы, где падеж словоформы однозначно сопоставляется
  параметру функции по таблице выше, а сама словоформа - в словаре из шага 1.5
  (идентификаторы программы + курируемый системный словарь).
- Typestate-проверка (шаг 4.1) ограничена конечным набором состояний, явно
  объявленных в `состояние:` - не общий dataflow-анализ произвольных
  предикатов.
